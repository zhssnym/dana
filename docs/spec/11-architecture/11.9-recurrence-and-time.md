### 11.9 Recurrence and time

- The 4.11 RRULE subset is implemented by an in-repo iterator module, not a runtime library. Reason, recorded: rrule.js is unmaintained (last publish about three years ago) and models results as reinterpreted UTC Dates, which collides with Dana's floating dates. The iterator is differential-tested against rrule 2.8.1 as a development-only oracle; where they disagree, RFC 5545 adjudicates, never the oracle.
- UNTIL is written in RFC 5545's DATE form, YYYYMMDD, and a rule string spelling it any other way is outside the 4.11 subset and answers 422 like any other free-form input. This is a reading of frozen 4.11 rather than a change to it, recorded at the P6 mid-package change control on 2026-08-10 because the grammar module and the acceptance suite would otherwise each derive it and could derive it differently. 4.11 defines the column as an RFC 5545 RRULE value string and calls UNTIL "a date, inclusive per RFC 5545"; within an RRULE that value is a DATE or DATE-TIME, and the DATE form carries no separators. The extended spelling 2026-07-27 is therefore not a valid value string of the RFC that 4.11 names, so admitting it would widen the frozen text rather than read it, and 4.11's own rule that only strings the preset builder can produce are valid independently forecloses accepting both spellings, since a builder emits one. The conventions line of `00-index.md` governs the dates this specification writes and the dates its wire fields carry, both of which stay extended, and both spellings are ISO 8601 in any case; the interior of a value string another standard defines is that standard's. rrule 2.8.1, the oracle above, parses the basic form, so nothing translates between our string and the oracle's, which is where a divergence the oracle exists to reveal would hide.
- Luxon 3 performs all IANA timezone math. Both DST rules of 8.6 are implemented explicitly in the fire-instant module because Luxon guarantees neither: for a nonexistent local time Luxon advances by the gap length (02:30 becomes 03:30) where 8.6 requires the first valid instant after the gap (03:00), so the module detects the gap and clamps; for an ambiguous local time Luxon's documentation declares the choice undefined, so the module selects the earlier instant itself. AC-144 and AC-145 pin the two rules, one each and by name against the raw behaviors above; AC-083 to AC-086 pin the zone arithmetic they sit on. Until the P7 mid-package change control of 2026-08-10 this sentence named only the second group and claimed it pinned both, which is the over-claim section 13 item 25 recorded at the P7 kickoff and which the amendment numbering AC-144 and AC-145 closed.
