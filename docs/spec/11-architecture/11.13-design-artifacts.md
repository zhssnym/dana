### 11.13 Design artifacts

**A feature request arrives as a GitHub issue, and the issue carries the design**,
including a technical one. There is no repository-committed design contract.

**Prototypes are references for design, never code to port.** A feature is shown through a
prototype where possible, and the prototype answers what it should look
like and how it should behave. The feature is then built on a branch against the real
client, its components, its query layer and `tokens.css`; nothing is copied from the
prototype's source. Building a frontend separately and connecting it afterwards is what
made two earlier integrations fail, and a prototype's shortcuts (fixture data keyed by name
rather than id, duplicated components, hard-coded values) are exactly what a port carries
across (11.15).

**`app/src/client/styles/tokens.css` is the only file that carries token values** (11.4).
No design file adjudicates a value above it; a prototype's colours and sizes inform an
edit to that file and never become a second source.
