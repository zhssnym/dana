### 11.3 Server

- Express 5. Route modules mirror section 7's resource groups. Every data route passes, in
  order: session resolution, CSRF verification (mutations only), rate limiting, then the
  handler, which resolves membership scope per 10.2 before touching rows. - Validation
  with zod 4; the schemas live in `app/src/shared/` and produce the 422 field errors of
  10.3. The client reuses them as convenience validation only (7.11). - Rate limiting with
  express-rate-limit, in-memory, keyed by authenticated user id, limits per 10.4. Counters
  reset on deploy; accepted. - Logging with pino to stdout. All log emission goes through
  one policy module that whitelists fields, making the 10.5 never-log list (task titles,
  notes, step titles, invite email addresses, tokens, session identifiers) structurally
  absent rather than filtered.
