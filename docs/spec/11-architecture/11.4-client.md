### 11.4 Client

Library versions: `app/package.json`. What follows is the choice each one embodies and the
constraint it imposes.

- Vite, React, and React Router in library mode only: no loaders, no actions, no framework
  mode. Data fetching belongs to the query layer alone.
- TanStack Query implements the 8.3 policy: refetch on window focus and after each own
  mutation; no other invalidation strategy exists.
- Forms with react-hook-form plus the shared zod schemas via @hookform/resolvers.
- Styling with Tailwind CSS 4, configured CSS-first through @tailwindcss/vite (there is no
  tailwind.config.js), and shadcn/ui components copied into
  `app/src/client/components/ui/`, composed with class-variance-authority, clsx and
  tailwind-merge and animated with tw-animate-css. The behaviour under those components is
  @base-ui/react, pinned exactly (11.15); the `shadcn` package is a copy-in generator and
  never a runtime dependency. Icons are lucide-react, imported per icon. The sans family is
  Inter, self-hosted through @fontsource-variable/inter, because a third-party font origin
  is one the 10.6 service worker cannot precache.
- Design tokens live in exactly one file, `app/src/client/styles/tokens.css`, as Tailwind
  @theme variables; it is the only place raw color, type, spacing, and radius values may
  appear. The rule governs values the design fixes, not data: a folder's colour is a
  member's own runtime choice carried on 7.4's my_color and rendered from the response, so
  changing tokens.css must never change what colour somebody's folder is.
- Calendar: the grid is Dana's own, a fixed six-week month of day cells with week and day
  zooms. Virtual instances from /views/planned/calendar render as ghost-classed rows, and
  the Q3C cell order, banners then timed then ghosts, is the order the cell renders them
  in. A day cell shows what fits and reveals the rest through 9.5's "+N more" control. The
  grid's accessibility and keyboard handling are Dana's to hold, which is why 9.1's roles
  table fixes the grid cell.
- PWA: vite-plugin-pwa builds the worker and the manifest, and registration follows the
  plugin's prompt-for-update flow (not autoUpdate), satisfying 10.6's non-forcing update
  rule: a worker that installs while another controls the page is announced and never
  applied without a click. The client may register the generated worker directly rather
  than importing virtual:pwa-register; the flow is the requirement, not the import.
  Fallback if the plugin fights the 10.6 contract: a hand-written service worker
  implementing precache, network-only API, and navigation fallback.
