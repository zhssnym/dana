### 11.15 Known hazards for implementers

Facts agents get wrong because training data lags the installed versions. Read before
touching the area; when in doubt, open the installed package's documentation, not memory.

- FullCalendar 7 imports standard plugins from @fullcalendar/react subpath entrypoints;
  the standalone @fullcalendar/daygrid package is v6-only. - Tailwind 4 is configured in
  CSS (@theme in tokens.css) through @tailwindcss/vite; there is no tailwind.config.js,
  and v3 configuration idioms are defects. - React Router runs in library mode; importing
  loader, action, or framework-mode APIs is a defect. - zod is v4; check its breaking
  changes against v3 idioms before writing schemas. - Luxon's raw DST gap and ambiguity
  behavior must never be used directly for fire instants (11.9). - Express 5 handles
  rejected promises in handlers natively; async wrapper hacks from Express 4 tutorials are
  noise. - PGlite is real Postgres but single-connection; tests must not assume parallel
  connections against one instance. What that costs is narrower than the sentence reads,
  measured at the P3 merge review after three sessions and a package fix had been routed
  on the wider inference. One connection serializes statements, not handler logic: two
  requests in flight interleave their awaits, so a read-then-write race is fully
  expressible on the default backend, and two concurrent step adds against a task holding
  49 steps do leave 51 where the count and the insert are not one decision. What genuinely
  needs a second connection is a second concurrent transaction. That is what a test must
  not assume here, rather than concurrency itself. - tsc compiles and emits a
  tsconfig-excluded file whenever any resolvable import references it, literal dynamic
  import() included. The dev-login exclusion of 11.6 therefore holds only when the loader
  uses a computed import specifier and treats the load failure in a production build as
  the route not existing (404). - Intl.DateTimeFormat as an IANA oracle is tolerant beyond
  the tzdb: it accepts ECMA-402 offset identifiers (+05:30) that are not IANA names and
  would break the 11.9 zone math, and it matches names case-insensitively. Every IANA
  validation goes through the shared validator (app/src/shared/timezone.ts), whose sign
  guard closes the offset hole; an independent re-check, such as the acceptance harness's,
  must refuse leading signs the same way. - **Stored client state serializes ids, never
  display names.** The v2 prototype keys folders, shelves and people by name because
  fixtures have no ids; a port that copies that shape breaks on the first rename. Saved
  views, arrangements and orders store uuids. - **Production carries two task rows** —
  `DoneRow` in `DonePage.tsx` duplicates `task-row.tsx` line for line. The v2 port
  reunifies them or records why not. - **The single-instance tick now carries three jobs**
  — reminders, trash purge, notification fan-out. The second-instance flag rule of 11.2
  has three reasons now; none of the jobs may move to request handlers.

**A request field can be lost in two different ways and only one of them is about unknown
fields.** Added 2026-09-03 with the #40 ruling in 11.14, because conflating the two is what
keeps `.strict()` being proposed as the answer to an incident it cannot see.

- **The schema does not declare the field.** 7.0 tolerates it, `z.object` strips it, the
  route answers its ordinary success. `PATCH /comments/:id` with `file_ids` is this (#94),
  and so is the shipping client's own `PATCH /shelves/:id` with `cover_file_id`, measured
  answering 200 with the cover unchanged: `patchShelfBody` does not name the field and
  `patchShelf` never writes the column, though 4.18 has it, `GET /shelves` returns it and
  `app/src/client/lib/page-identity.ts` sends it. **What catches this class:** logging an
  unknown key, which is admitted and unbuilt (11.14), or declaring the field and refusing it
  with `z.never({ error: … }).optional()`, which answers 422 naming the field without
  making the object strict. **What does not:** the compiler, on either side.
- **The schema declares the field and the route does not act on it.** This is the expensive
  one and the one people mean when they cite the four-package reminder loss in
  `app/src/shared/tasks.ts`. Every unknown-key mechanism is blind to it, strictness
  included, because the key is known. **What catches this class:** a criterion, which is
  what AC-149 is, and the rule that a request schema gaining a field gains the code reading
  it in the same change. Nothing structural does.

**And a `.strict()` schema cannot report itself through this tree's 422 formatter as it
stands.** zod 4 gives an unrecognized key an **empty** issue path and the code
`unrecognized_keys`; `sendValidationError` drops empty-path issues and then looks for a
`custom` one, so the caller is answered `422 validation_failed` with the message "A JSON
object body is required." — no field named, and untrue. Anyone adding the first strict
schema teaches that formatter first. Measured 2026-09-03 by calling the formatter with a
real strict refusal.

The five below moved here on 2026-09-01 from retired section 13, where they had been filed
as open questions. None is a question: each is a fact about an installed library, or about
what this build can and cannot check, and each carries the condition under which it should
be looked at again.

- **The Drizzle migrator wraps each run, not each file, in one transaction**, so all
  pending files commit or roll back together. It takes no lock while applying, which is
  safe exactly while production is one instance with serial deploys, and 11.1's
  second-instance checklist names the consequence. The acceptance harness serializes its
  own parallel-worker migrations under an advisory lock. Re-verify both facts in the
  installed source on any drizzle-orm upgrade. - **openid-client leaves code-flow ID token
  signatures unverified by default.** Version 6 takes OIDC Core's permission to rely on
  the token endpoint's TLS channel instead. The acceptance criteria forbid that, so
  `app/src/server/auth/oidc.ts` sets `enableNonRepudiationChecks`, verified both ways
  against the installed version: without it a rogue-key token established a session, with
  it the token is refused. Re-verify on any upgrade that the switch exists, still forces
  verification, and that the default has not moved. - **Drizzle statement errors embed
  bound parameters.** `DrizzleQueryError`'s message carries the failed SQL and its bound
  values, and `Error.stack` opens with that message, so logging a database error verbatim
  leaks row content against 10.5. Proven with an invite email address during P1. The boot
  file's 5xx handler strips the wrapper's message and keeps its frames. Re-verify the
  message shape on any drizzle-orm upgrade. - **The two DST rules of 8.6 have no oracle,
  by construction.** A nonexistent local time has no correct answer and an ambiguous one
  has two, so both rules are Dana policy chosen where the standard is silent, and no
  library implements them. Luxon is not merely absent here, it is an anti-oracle for
  exactly these two cases: it advances by the gap length where 8.6 requires the first
  valid instant after it, and leaves the fold undefined where 8.6 requires the earlier
  instant. What is owed instead is the anti-oracle assertion in the fire-instant module's
  own tests, asserting that raw Luxon and the module differ in each named way, so the
  override is proven necessary rather than assumed. Fixtures use historical transitions in
  zones stable for decades, never a future date and never a recently changed zone, because
  the runtime and the embedded engine carry tzdb copies that move independently. -
  **@base-ui/react is pinned exactly, and its behaviour is the accessibility contract the
  browser leg measures.** The primitives supply focus management, escape handling, menu
  typeahead and the expanded state of every disclosure, which is what 9.1's addressing
  sentence and the browser leg assert from the outside. The pin is exact rather than a
  range because a minor release that moves focus or changes a rendered role is invisible
  to every check this build has except the browser cases, which run against whatever is
  installed. Any upgrade of it or of the shadcn components beside it re-runs the browser
  leg before merging, and a role or accessible name that moved is the finding rather than
  the failure.
