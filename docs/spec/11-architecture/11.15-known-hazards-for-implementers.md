### 11.15 Known hazards for implementers

Facts agents get wrong because training data lags the installed versions, or because the
code shows the workaround and not the assumption it defends against. Read before touching
the area; when in doubt, open the installed package's documentation, not memory.

**Library recall**

- Tailwind 4 is configured in CSS (@theme in tokens.css) through @tailwindcss/vite; there
  is no tailwind.config.js, and v3 configuration idioms are defects.
- React Router runs in library mode; importing loader, action, or framework-mode APIs is a
  defect.
- zod is v4; check its breaking changes against v3 idioms before writing schemas.
- Luxon's raw DST gap and ambiguity behavior must never be used directly for fire instants
  (11.9).
- Express 5 handles rejected promises in handlers natively; async wrapper hacks from
  Express 4 tutorials are noise.
- PGlite is real Postgres but single-connection. One connection serializes statements, not
  handler logic: two requests in flight interleave their awaits, so a read-then-write race
  is fully expressible on PGlite. What genuinely needs a second connection is a second
  concurrent transaction, and that is what a test must not assume there.
- tsc compiles and emits a tsconfig-excluded file whenever any resolvable import
  references it, literal dynamic import() included. The dev-login exclusion of 11.6
  therefore holds only when the loader uses a computed import specifier and treats the
  load failure in a production build as the route not existing (404).
- Intl.DateTimeFormat as an IANA oracle is tolerant beyond the tzdb: it accepts ECMA-402
  offset identifiers (+05:30) that are not IANA names and would break the 11.9 zone math,
  and it matches names case-insensitively. Every IANA validation goes through the shared
  validator (`app/src/shared/timezone.ts`), whose sign guard closes the offset hole; any
  independent re-check must refuse leading signs the same way.
- **The Drizzle migrator wraps each run, not each file, in one transaction**, so all
  pending files commit or roll back together. It takes no lock while applying, which is
  safe exactly while production is one instance with serial deploys (11.1). Re-verify in
  the installed source on any drizzle-orm upgrade.
- **openid-client leaves code-flow ID token signatures unverified by default**, relying on
  the token endpoint's TLS instead. The acceptance criteria forbid that, so
  `app/src/server/auth/oidc.ts` sets `enableNonRepudiationChecks`. Re-verify on any
  upgrade that the switch exists, still forces verification, and that the default has not
  moved.
- **Drizzle statement errors embed bound parameters.** `DrizzleQueryError`'s message
  carries the failed SQL and its bound values, and `Error.stack` opens with that message,
  so logging a database error verbatim leaks row content against 10.5. The 5xx handler
  strips the wrapper's message and keeps its frames. Re-verify the message shape on any
  drizzle-orm upgrade.
- **@base-ui/react is pinned exactly, and its behaviour is the accessibility contract.**
  The primitives supply focus management, escape handling, menu typeahead and the expanded
  state of every disclosure, which 9.1 fixes. A minor release that moves focus or changes a
  rendered role is invisible to everything but the browser leg, so any upgrade of it or of
  the shadcn components beside it runs the browser leg before merging, and a role or
  accessible name that moved is the finding rather than the failure.

**Dana's own traps**

- **The two DST rules of 8.6 have no oracle, by construction.** A nonexistent local time
  has no correct answer and an ambiguous one has two, so both rules are Dana policy and no
  library implements them. Luxon is an anti-oracle for exactly these cases (11.9); the
  fire-instant module's tests assert that raw Luxon and the module differ in each named way.
  Fixtures use historical transitions in zones stable for decades, never a future date or a
  recently changed zone, because the runtime and the embedded engine carry tzdb copies that
  move independently.
- **A `fetch` written anywhere in `app/src/client` except `app/src/client/api/http.ts`
  skips the CSRF header of 11.6 and the `tz` parameter of 7.0**, and the server's 403 or
  422 then reads as an API fault. `app/eslint.config.ts` forbids it outside that file.
- **Stored client state serializes ids, never display names.** Saved views, arrangements
  and orders store uuids; state keyed by a name breaks on the first rename. Prototypes key
  fixtures by name because they have no ids, which is one reason they are never ported
  (11.13).
- **The single-instance scheduler pass carries every background duty** (11.7). Each is a
  reason the single-instance rule of 11.1 must be flagged before it changes, and none may
  move to request handlers.
- **A request field can be lost in two ways, and only one is about unknown fields.**
  - *The schema does not declare it*: 7.0 tolerates it, `z.object` strips it, and the route
    answers its ordinary success. `parseBody` (`app/src/server/http/parse-body.ts`) logs
    such keys at the top level only; a key nested in a declared object is still dropped in
    silence. Declaring the field as `z.never({ error: … }).optional()` refuses it with a 422
    naming it. The compiler catches neither.
  - *The schema declares it and the route does not act on it*: every unknown-key mechanism,
    strictness included, is blind to this, because the key is known. Only a criterion
    catches it, and the rule that a request schema gaining a field gains the code reading it
    in the same change. Nothing in `app/src/shared/` is strict, and 11.14 rules that none
    of it becomes strict.
