### 12.14 Comments and likes

Threads, their permissions, likes, and the files hung on a comment. The file itself is
12.15.

- AC-204 Given a reply to a reply, then 422; comment threads hold one level.
- AC-205 Given a comment in a folder, when a non-member reads or writes its thread, then the 10.2 not-found shape; when the author or the folder owner deletes it, then success; when another member tries, then 403.
- AC-206 Given the same user liking a comment twice, then one like exists; unliking removes it.
- AC-207 Given a comment in a thread with participants, then each participant except the actor gains a notification.
- AC-290 Given a comment carrying a file, when the thread is read, then that comment's `files` carries the file's id, name, mime and bytes as 4.16 stores them and no bare-id form rides beside it; and the create answer carries the same (spec 7.14 as amended by item 57, B5).
- AC-344 Given a comment posted with several file ids, then one comment is created carrying all of them and the thread reads them back in the order they were sent, not the order they were uploaded; given the one-file `file_id` spelling, then its file is attached and not dropped; given one id naming a file of another folder, then 422 and no comment is created.
- AC-345 Given a comment naming ten files, then 201, all ten are attached, and the thread reads them back in the order they were sent rather than in any order the files or their ids carry; given eleven, then 422 naming `file_ids`; given the same id twice, or `file_ids` sent beside `file_id`, then 422; and in every refusal no comment exists afterwards.
- AC-364 Given a comment carrying an image, then both the create answer and the thread read carry that picture's width and height beside 4.16's other columns, so a reader who did not attach it draws the tile at the right proportion before the bytes arrive; and given a comment carrying a document, then both are null on both shapes (spec 7.14 as amended, 4.16 as amended by migration 0009; issue #27).
