### 12.14 Comments and likes

Threads, their permissions, likes, and the files hung on a comment. The file itself is 12.15.

- AC-204 Given a reply to a reply, then 422; comment threads hold one level.
- AC-205 Given a comment in a folder, when a non-member reads or writes its thread, then the 10.2 not-found shape; when the author or the folder owner deletes it, then success; when another member tries, then 403.
- AC-206 Given the same user liking a comment twice, then one like exists; unliking removes it.
- AC-207 Given a comment in a thread with participants, then each participant except the actor gains a notification.
- AC-290 Given a comment carrying a file, when the thread is read, then that comment's `files` carries the file's id, name, mime and bytes as 4.16 stores them with no bare-id form beside it, and the create answer carries the same (spec 7.14).
- AC-344 Given a comment posted with several file ids, then one comment carries all of them and the thread reads them back in the order sent; the one-file `file_id` spelling attaches its file; and one id naming a file of another folder is 422 with no comment created.
- AC-345 Given a comment naming ten files, then 201 with all ten attached in the order sent; eleven is 422 naming `file_ids`; the same id twice, or `file_ids` beside `file_id`, is 422; and no refusal leaves a comment.
- AC-364 Given a comment carrying an image, then the create answer and the thread read carry its width and height beside 4.16's other columns; for a document both are null on both shapes (spec 7.14, 4.16).
- AC-381 Given a comment carrying attachments, when PATCH /comments/:id sends `file_ids`, then the set becomes exactly those ids in that order, the words untouched and 4.15's edited stamp set; an omitted field leaves attachments unchanged; a wordless comment's attachments are editable; and the answer carries the fresh comment with files and the `edited` flag (spec 7.14, 4.15, 4.16).
- AC-382 Given a comment with words and attachments, when `file_ids: []` is sent, then every attachment is removed and the words stay; given a wordless comment, then the empty list is 422 naming `file_ids` and removes nothing, a comment with neither words nor files being one only DELETE produces (spec 7.14, 4.15).
- AC-383 Given an attachment edit naming a file outside the comment's folder, whether the author's own or another account's, then 422 naming `file_ids` with one message for both and attachments unchanged; eleven ids, a repeated id, or the `file_id` spelling is 422 while ten is admitted; and a folder member who is not the author gets 403 (spec 7.14, 10.2, 10.3, 11.14).
- AC-790 Given another member's comment in a shared folder, then a Full-control member who owns nothing is offered Delete on both conversation surfaces and `DELETE /comments/:id` answers 204; the folder owner lowered to Can comment is offered no Delete and gets 403; a member at Can view is offered no Edit, Delete, like or Reply on any comment, their own included, with the composer shown disabled carrying the sentence saying what commenting needs; at every access preset moderation belongs to Full control and changing one's own comment to Can comment, the screen and the route both resolving through `app/src/shared/folder-actions.ts`; and at Trash a Full-control non-owner may permanently delete a trashed task (204) but not a trashed folder (403, custody required), the demoted owner may do neither, and `GET /trash` carries `my_access` beside `is_owner` (spec 7.13, 7.14, 10.2).
