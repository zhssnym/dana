### 12.16 Duplicating, importing and workflow files

Copying a folder or a task, and the workflow file that carries structure and refuses identity: ids, people, due dates and states, a step's tick included, never travel in one.

- AC-200 Given a folder duplicated with a timezone named, then the copy carries tasks, sections, paragraphs and section assignments; carries no members, comments, assignees or completion; re-anchors spent due dates on that zone's today and keeps future ones, the intervals holding; and belongs to the duplicator alone (spec 8.1).
- AC-201 Given a workflow file naming ids, members, dates, or statuses, when imported, then only structure and titles are created; given a file over the 10.3 import caps, then 422.
- AC-237 Given a workflow file at 10.3's block ceiling, then it imports; a file over 1000 tasks answers 422 naming the field, and a body over 3 MB answers the parser's 400.
- AC-272 Given a workflow file whose task carries notes, a star, a repeat, a reminder and step titles, when imported, then the task carries all five with steps in file order; and given the same file also carrying an id, an assignee, a due date, a status and a ticked step, then none of those arrive: the task is pending, assigned to the importer, and its steps are unticked.
- AC-273 Given a workflow file whose task carries a repeat or a reminder, when imported with a tz, then the task is dated on that zone's today with the repeat and reminder stored against it; imported with no tz, then 422 naming tz and no folder is created; and a file carrying neither imports with no tz, its tasks undated.
- AC-277 Given a task assigned to another member with notes, a done step, a conversation and a passed due date, when a member duplicates it naming their timezone, then the copy is assigned to the copier, carries title, notes and steps all undone, no comment, and a due date of that zone's today; a task due ahead keeps its date; and a non-member of the task's folder gets 404 (spec 8.1).
- AC-282 Given a workflow file whose task carries a repeat, when chosen through the sidebar's Import control, then the request carries the viewer's tz, the folder appears in the Library holding the task; and a file that is not a workflow sends nothing and the person is told.
- AC-292 Given a folder duplicated, then the answer carries `shifted_days`, the days the plan moved when its earliest date was spent and 0 otherwise, and the copy's History line says "dates moved to start today" exactly when it is positive (spec 7.16, 9.6).
- AC-294 Given an open task, when its More actions "Duplicate" is pressed, then the task is copied with `POST /tasks/:id/duplicate`, the undo bar says so and the copy is on the page; and when "Make this a folder…" is pressed, then one folder named after the task is made with `POST /folders` and the task moved into it with `PATCH /tasks/:id`. A task row carries no menu of its own (spec 9.3).
- AC-341 Given a workflow file chosen through the sidebar's Import, then a toast says what was made and how many tasks it holds, the imported folder opens, and a name the Library already has arrives as "<name> (imported)" (spec 9.1, 7.16).
- AC-376 Given a duplicate that would re-anchor a spent due date with no timezone named, then 422 naming tz and nothing is written; a timezone that is not an IANA identifier is 422 naming tz whether or not a date would move; and a source with no due date, or one ahead of today in every zone, duplicates without a timezone (spec 7.16, 8.1, 9.6, 10.3).
- AC-820 Given a folder page with two Sections, Tasks under each and a root paragraph after them, when saved as a workflow file and imported into another account, then every Task arrives under its Section and the paragraph at the root, the file stating membership by position and naming a Section only where position would be wrong (spec 7.16, 4.17).
- AC-821 Given a Task moved from one Section to another, when the folder is saved as a workflow file, then the file places it under the Section it was moved to and an import puts it there, while a file saved before the move carries the earlier Section (spec 7.16, 4.17).
- AC-822 Given a folder page holding paragraphs, a nested Section, a list nested two deep, a ticked checklist item, a quote, a callout and a code block, when saved as a workflow file and imported, then every block keeps its kind, order, heading depth and list parent, the two parent relations travelling independently (spec 7.16, 4.17).
- AC-823 Given a folder page holding a picture, when saved as a workflow file, then the file carries an explicit placeholder at its position naming the kind, the writer reports how many placeholders it wrote, and the bytes carry no file, files-row or source-folder id; and importing it creates no image block or files row, the surrounding writing keeping its order (spec 7.16, 7.15, 4.16, 10.2).
- AC-824 Given a version 4 workflow file whose page claims an undefined block kind, work written both on the page and beside it, or an index resolving to nothing, then 422 naming the field and no folder is created; and the same page inside a version 1 file is dropped as a foreign arrangement and the file imports (spec 7.16, 10.3, 7.0).
- AC-825 Given the file "Save as workflow" writes from a composed folder page, when imported and the imported folder saved again, then the second file is byte for byte the first less its placeholders, a third save equals the second, and the imported page's rich content equals the source's (spec 7.16, 4.17).
- AC-849 Given a Folder with a named, non-empty Purpose holding list structure and Dana Links, when the Folder is duplicated, then the copy's native Purpose keeps a fresh facet id, every Purpose block has a fresh id, list ancestry points only within the copy, the display-name override and content survive, media follows the Folder-page copy and quota path, and only links to the source Folder, source Purpose and Tasks copied in the same act are rewritten to their copies (spec 7.16).
- AC-850 Given Purpose supplied to Save-as-workflow, then the writer emits workflow version 5 with the optional Purpose display name, portable Purpose writing, file-local list ancestry and media as omitted placeholders; importing it writes the new Folder's native Purpose with fresh block ids and authored hrefs preserved; versions 1 through 4 stay readable; and a caller supplying no Purpose still gets version 4 (spec 7.16).
- AC-870 Given a folder whose Tasks depend on one another and on a Task in another folder, when saved as a workflow file and imported into another account, then the file carries no live id, the internal dependencies exist between the imported Tasks and the external one does not (spec 7.16, #207).
- AC-871 Given a hand-written workflow file whose task keys depend across two of its folders and on a key it does not declare, when imported, then the cross-folder edges exist and the undeclared one is skipped; and a file whose dependencies form a cycle is 422 naming `depends_on` with no folder created (spec 7.16, #207).
