### 12.16 Duplicating, importing and workflow files

Copying a folder or a task, and the workflow file that carries structure and refuses
identity.

- AC-200 Given a folder duplicated with a timezone named, then the copy carries tasks, sections, paragraphs, and section assignments; carries no members, comments, assignees, or completion; re-anchors spent due dates on that zone's today and keeps future ones, the intervals holding; and belongs to the duplicator alone (the zone since 2026-09-04, issue #76; 8.1).
- AC-201 Given a workflow file naming ids, members, dates, or statuses, when imported, then only structure and titles are created; given a file over the 10.3 import caps, then 422.
- AC-237 Given a workflow file at 10.3's block ceiling, then it imports, the 3 MB body row being sized above the largest legal file so every cap in the limits table is reachable; a file over 1000 tasks answers 422 naming the field, and a body over 3 MB answers the parser's 400.
- AC-272 Given a workflow file whose task carries notes, a star, a repeat, a reminder and step titles, when it is imported, then the created task carries all five and its steps arrive in the file's own order; and given the same file also carrying an id, an assignee, a due date, a status and a ticked step, then the imported folder holds none of those five: the task is pending, unstarred by nothing but its own flag, assigned to the importer, and its steps are untended.

**AC-272's second half asserts an absence**: the widened workflow file still refuses ids,
people, due dates and states, a step's tick included. The refusal is what keeps the widening
from becoming an import of somebody else's account.

- AC-273 Given a workflow file whose task carries a repeat or a reminder, when it is imported with a tz, then the created task is dated on that zone's today and the repeat and the reminder are stored against it; and given the same file imported with no tz, then 422 naming tz and no folder is created; and given a file carrying neither a repeat nor a reminder, then it imports with no tz exactly as it did before and its tasks stay undated.
- AC-277 Given a task assigned to another member, carrying notes, a done step, a conversation and a due date that has passed, when a member duplicates it naming their timezone, then the copy is assigned to whoever made the copy, carries the title, the notes and the steps with every step undone, carries no comment, and its due date is that zone's today — the same source duplicated from two zones a day apart landing on two different days (the zone since 2026-09-04, issue #76; 8.1); given a task whose due date is still ahead, then the copy keeps that date; and given a person who is not a member of the task's folder, then the duplicate is 404.
- AC-282 Given a workflow file of 7.16 as widened, whose task carries a repeat, when it is chosen through the sidebar's Import control, then the request carries the viewer's tz, the folder appears in the Library, and the task is in it; and given a file that is not a workflow at all, then nothing is sent and the person is told.
- AC-292 Given a folder duplicated, then the answer carries `shifted_days`, the days the plan moved when its earliest date was spent and 0 when every date kept, and the copy's History line says "dates moved to start today" exactly when it is positive (spec 7.16 as amended by item 58, E; 9.6; ledger L-055).
- AC-294 Given a task row, when its More actions "Duplicate" is pressed, then the task is copied with `POST /tasks/:id/duplicate`, the undo bar says so, and the copy is on the page; and when "Make this a folder…" is pressed, then one folder named after the task is made with `POST /folders`, the task is moved into it with `PATCH /tasks/:id`, a toast says so with an undo, and the row leaves the page (spec 9.3, 7.16, 7.4, 7.6; ledger L-007).
- AC-341 Given a workflow file chosen through the sidebar's Import, then a toast says what was made and how many tasks it holds, the imported folder opens, and a file naming a folder the Library already has arrives as "<name> (imported)" rather than as a second folder of that name (spec 9.1, 7.16).
- AC-376 Given a duplicate that would re-anchor a spent due date, when the request names no timezone, then 422 naming tz and neither the copy nor any part of it is written; given a timezone that is not an IANA identifier, then 422 naming tz whether or not a date would have moved; and given a source with no due date, or one whose date is ahead of today in every zone, then the duplicate answers as it did before the parameter existed (spec 7.16 as annotated 2026-09-04, 7.8's precedent, 8.1, 9.6, 10.3; issue #76).
