### 12.1 Schema and migrations

Constraints asserted against section 4, and the migrations that changed data already
stored. What a deletion does to those rows is 12.20.

- AC-001 Given migrations on an empty database, when the constraint catalog is diffed against section 4, then every table, FK with its on-delete action, CHECK, unique index, and index exists.
- AC-002 Given inserts violating INV-6 or INV-8 (due_time without due_date; completed without completed_at), when attempted, then the database rejects them.
- AC-003 Given a second is_default folder for the same owner, when inserted, then rejected (INV-2).
- AC-004 Given a connection row with user_a_id greater than user_b_id, when inserted, then rejected (INV-9).
- AC-211 Given default folders named Inbox, when the migration runs, then they are named Desk; given a default the owner renamed, then its name is kept.
- AC-372 Given migration 0012, then the database itself refuses a shelf row carrying a picture and a preset at once, a preset that is not a key, and a crop outside 0 to 100, while admitting one source or none; and refuses a file with no folder whose kind is none of avatar, cover and image, admitting those three (the third since migration 0015 and issue #167, a shelf page's picture belonging to the person as that page's cover does) (spec 4.16, 4.18, 12.1, migrations 0012 and 0015).
- AC-380 Given migration 0013, then a value outside 9.5's three zooms is refused twice over: the settings bundle answers 422 naming `calendar_zoom` and leaves the stored value as it was, and the database itself refuses the row by `user_settings_calendar_zoom_check` when the column is written directly, while admitting each of `day`, `week` and `month`; AC-001 asserting that constraint's name and column and never what its expression does (spec 4.10 as annotated, 7.2 as annotated, 12.1; issues #140, #142).
