### 12.1 Schema and migrations

Constraints asserted against section 4, and the migrations that changed data already
stored. What a deletion does to those rows is 12.20.

- AC-001 Given migrations on an empty database, when the constraint catalog is diffed against section 4, then every table, FK with its on-delete action, CHECK, unique index, and index exists.
- AC-002 Given inserts violating INV-6 or INV-8 (due_time without due_date; completed without completed_at), when attempted, then the database rejects them.
- AC-003 Given a second is_default folder for the same owner, when inserted, then rejected (INV-2).
- AC-004 Given a connection row with user_a_id greater than user_b_id, when inserted, then rejected (INV-9).
- AC-211 Given default folders named Inbox, when the migration runs, then they are named Desk; given a default the owner renamed, then its name is kept.
- AC-372 Given migration 0012, then the database refuses a shelf row carrying a picture and a preset at once, a preset that is not a key, and a crop outside 0 to 100, while admitting one source or none; and refuses a file with no folder whose kind is none of avatar, cover and image, admitting those three (spec 4.16, 4.18).
- AC-380 Given migration 0013, then a `calendar_zoom` outside 9.5's three zooms is refused twice over: the settings bundle answers 422 naming the field and leaves the stored value unchanged, and the database refuses a direct write by `user_settings_calendar_zoom_check`, while admitting each of `day`, `week` and `month` (spec 4.10, 7.23).
- AC-415 Given migration 0016 on an existing database, when it completes, then `page_blocks` and `tasks` carry nullable C-collated, format-constrained `page_position` columns, folder/shelf ordering indexes exist, page blocks carry a constrained self-FK `section_block_id`, existing shelf blocks keep their order, and every existing folder's loose tasks, Sections, opening prose, Section tasks and remaining prose/images receive keys in exactly the order the pre-migration folder page drew them (spec 4.5, 4.17).
- AC-1014 Given a database migrated through 0037 holding nested list items, writing under a toggle and a Task document, when migration 0038 runs, then every stored row is unchanged with a null `toggleable`; afterwards a Task-homed block takes a block parent, a `section` or a row naming itself as parent is refused by `page_blocks_list_parent_kind_check`, and `toggleable` on anything but `heading1`–`heading3` is refused by `page_blocks_toggleable_kind_check` (spec 4.17).
