### 12.4 Folders and membership

Who may rename, delete, join and leave a folder, and the identity every member reads.
What a deletion does is 12.20; what a folder page draws is 12.9.

- AC-011 Given a non-owner member, when renaming the folder, then 403.
- AC-012 Given the owner, when renaming, then 200 and every member reads the new name.
- AC-013 Given the owner of a default folder, when deleting it, then 409.
- AC-015 Given a non-owner member, when deleting the folder, then 403.
- AC-016 Given the owner removes a member holding assigned tasks, then those tasks are unassigned, the member's My Day entries for the folder's tasks are deleted, and their access ends.
- AC-017 Given a removal leaves exactly one member, then every unassigned task in the folder is assigned to the remaining member (INV-5).
- AC-018 Given a non-owner member leaves, then the same cleanup as removal runs.
- AC-019 Given the owner leaves a folder with other members, then ownership transfers to the earliest-joined member (tie: lower user id) and the leave proceeds.
- AC-020 Given the owner is the sole member, when leaving, then 409 with the delete-instead message.
- AC-021 Given two members race to add the same person, when both POST, then one 201 and one 409 (INV-10).
- AC-022 Given a member adds someone they hold no roster connection with, when POST members, then 422.
- AC-023 Given a member sets a personal label and color, then another member's view of the folder shows no label change.
- AC-173 Given folders in the sidebar whose 4.3 identity colours differ and one with no colour set, then each row is painted with its own folder's colour and not with another's, a row for an uncoloured folder still renders its name and its pending count, and two folders carrying different colours do not render the same paint. (Reworked at S17a; the text it replaces read the personal column 9.6 retired, and the reasoning sits with S17a's criteria at the foot of this section.)

**AC-173 asserts the dot as identification rather than as a colour value**, for the reason the
tokens file itself gives: the swatch is always beside a name, so what a test can hold the
client to is that the dot is present, that it carries the folder's own colour rather than one
colour for every row, and that a folder with no colour set still renders a row rather than a
gap.

- AC-181 Given the "New folder" action of 9.1, then it opens a dialog taking a name and creating the folder.
- AC-193 Given a non-owner member, when they rename the folder, then 403; when they set its icon, colour, cover, or description, then success, and every member reads the same identity.
- AC-202 Given an owner and another member, when ownership is transferred to that member, then owner_id changes and the previous owner may leave; the default successor is the longest-standing member per 8.9.
- AC-217 Given a folder shared with the viewer, then its menu offers "Leave folder…" and neither Rename nor Delete folder, and its page title is not editable; given an owned folder, then the reverse.
- AC-243 Given a folder whose icon and colour are set once from its own page's mark, then the same glyph and the same colour are drawn on that folder's sidebar row, on the folder chip of a task in it wherever that task's row is listed, and on that folder's entry in the tab strip's "New tab" menu; and given a second folder wearing a different glyph, then no two of those surfaces draw the first folder's glyph for the second.
- AC-246 Given one folder the viewer owns, then the acts its menu offers in the sidebar's Library and the acts its own page's menu offers come from one declared contract: both menus offer History, Rename, Move to shelf, Copy link, Duplicate, Save as workflow and "Delete folder…", those acts stand in the same relative order in both, and every other item either menu carries is one of the four that belong to a surface rather than to the folder, the sidebar's "Add task", "New folder group" and "Open in a new tab" and the page's "Transfer ownership"; and given a folder the viewer is only a member of, then both menus offer "Leave folder…" in Delete folder's place and neither offers Rename or Delete folder, which is AC-217's rule read on both surfaces rather than on one.
