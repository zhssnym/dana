### 12.13 Events, history and notifications

The events row every mutation writes, the History surface it feeds, and the notification it raises.

- AC-184 Given any authenticated mutation that changes a task, folder, shelf, or comment, when it succeeds, then exactly one events row records it, carrying the actor, the verb, and the subject.
- AC-185 Given a folder member, when they list the folder's events, then events return newest first; given a non-member, then the 10.2 not-found shape.
- AC-186 Given an event whose subject the viewer cannot read, when they read events by subject, then the 10.2 not-found shape.
- AC-187 Given a task assigned to another member, when the assignment commits, then the assignee gains one unread notification and the actor gains none.
- AC-188 Given unread notifications, when the recipient marks one read and then all read, then read_at is set accordingly and the unread count agrees at each step.
- AC-213 Given events older than 90 days, when the 11.7 pass runs, then they are purged and newer events remain.
- AC-218 Given unread notifications, then the bell's accessible name carries the count; pressing a row opens its subject and marks it read; Mark all read zeroes the badge.
- AC-311 Given a task with an assignee, when another member comments on it, then the assignee gains a notification whether or not they have spoken, the event's detail names the task, the notification carries the task's id, and the actor is not notified (spec 4.14, 7.12, 7.14, 9.12).
- AC-333 Given a folder in which a task was added and a person invited, when History is opened, then each row reads as a sentence naming who did what ("<name> added “<task>”", "<name> invited <email>"), and the "Edited N ago" line is a line rather than a second door to the record (spec 9.6, 7.12, 4.13).
- AC-1024 Given a page with a member and a person who is not a member, when the author saves a paragraph whose rich text mentions both (`mention: { user_id }` on a run), then the page read returns the mention, the member gains exactly one `mentioned` notification naming the page and the non-member gains no notification and no `mention_notices` row; re-saving the same block notifies nobody again; a mention naming no existing person is refused and writes nothing; a Task document mention names the Task; and deleting the member's account removes their `mention_notices` rows; in a Discussion thread, a post mentioning the member and a non-member tells the member once with the detail "mentioned you in “<thread>”" and no `commented` notification for that post, tells the non-member nothing, an edit of the post tells nobody again, and a post mentioning no existing person is refused (spec 4.13, 4.14, 4.15, 8.10).
