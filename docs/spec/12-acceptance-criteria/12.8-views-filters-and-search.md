### 12.8 Views, filters and search

Tasks, Scheduled, Important, All, Done, the calendar, saved views and the search overlay.
Today is 12.7; a folder page's own regions are 12.9.

- AC-051 Given undated tasks in the Desk and in a custom folder, then Tasks renders Desk rows ungrouped on top and the rest under folder headings. (Desk, called Inbox in this criterion's text until 2026-09-04 and issue #98; the default folder has been named Desk since RFC 0005.)
- AC-052 Given dated tasks including an all-day and a timed task on one date, then Planned lists by date ascending with the all-day row first.
- AC-053 Given an abandoned undated task, then it renders faded in Tasks and All, and is absent from My Day and Done.
- AC-054 Given important tasks with and without dates, then Important shows the dated block first (soonest first) and undated after (newest first).
- AC-055 Given un-star on a row in Important, then the next fetch omits it and the task is otherwise unchanged.
- AC-056 Given 120 completed tasks, then Done pages by 50 using the (completed_at, id) cursor, grouped by completion day in the viewer's timezone.
- AC-057 Given a query matching tasks in accessible and inaccessible folders across all three statuses, then search returns only accessible rows grouped pending, abandoned, completed.
- AC-070 Property: for randomized datasets, All equals Tasks union Planned exactly, the two are disjoint, every non-completed task appears in All, and every completed task appears in Done.
- AC-095 Given Important, All, and Done toggled hidden, then the sidebar omits them while their URLs still render the pages (visibility is navigation preference only).
- AC-096 Given the Done page, then no floating add button and no quick-add row exist on it.
- AC-099 Given star hover on Important, then the tooltip names the task's home page with its date or folder; on any other page it confirms importance.
- AC-125 Given GET /views/planned/calendar with end minus start greater than 62 days, then 422 naming the range; given exactly 62 days, then 200.
- AC-126 Given tasks due inside and outside an accepted calendar range in all three statuses, when GET /views/planned/calendar, then real carries exactly the accessible rows due within the inclusive bounds, in all three statuses, ordered all-day banners before timed rows within each date.
- AC-127 Given more than 20 accessible tasks matching a query, then GET /search answers 20 rows with a next_cursor, and the cursor's page carries the rest in Q8's order with no overlap and no gap.
- AC-128 Given a search query that is shorter than 2 or longer than 100 characters after trimming, then 422 naming the field; given 2 and given 100, then 200.
- AC-129 Given more than 1000 rows qualifying for a capped list, then the response carries at most 1000 of them and truncated is true; given fewer, then every row is present and truncated is false.
- AC-130 Given any view endpoint called with a tz that is not a valid IANA identifier, or with no tz at all, then 422 naming the field; given a valid one, then 200.
- AC-131 Given a search query containing a percent, an underscore, or a backslash, then those characters match themselves and the row carrying the literal character is returned while the row that only satisfies the wildcard reading is not.

**AC-131's backslash case is the one worth naming**, because it fails in the opposite
direction from the other two and was measured against real Postgres rather than reasoned
about. An unescaped percent or underscore returns an extra row. An unescaped backslash is read
as LIKE's own escape character, so the pattern finds the row without the backslash and misses
the row the user typed: a leak that loses the right answer instead of adding wrong ones, and
the harder of the two to notice in use.

- AC-156 Given the search overlay of 9.9, then both shortcuts open it, the input debounces at 300 ms, results render grouped under Pending, Abandoned and Completed, enter opens the first result, and the footer carries its copy.
- AC-158 Given an account with no tasks, then each page renders the empty-state copy section 6 gives it, the My Day recap is hidden rather than empty, and the calendar shows the bare grid with no message.
- AC-167 Given the window bar filter's important switch on Today, then it filters the rows already fetched and issues no request, and turning it off restores them without one either.
- AC-177 Given the Planned calendar's month zoom, then its days are grid cells within a grid, the grid holds six weeks beginning on Monday, and a day holding more rows than its cell renders shows a "+N more" control that reveals the remainder.
- AC-209 Given a saved view naming an assignee by id, when that person's display name changes, then the view still matches them.
- AC-210 Given a search term matching a page paragraph, a shelf name, and a step title, then each returns under its kind; given a reader consuming only the v1 task results, then its view of the response is unchanged.
- AC-222 Given a filter set on Scheduled, when the viewer navigates away and returns, then it holds; when they visit Today, then Today's filter is independent.
- AC-245 Given Today's computed "Today" section and Assignments' per-person section, neither of which any package made collapsible, then each is a named region and a control carrying that name whose expanded state says whether the section is open, and when that control is pressed then the rows under it are no longer on the page while the region and its control remain.
- AC-247 Given each of Today, Scheduled, Assignments, Important, All and Anytime, then the page's mark is drawn above its title rather than inline beside it, the page's fact where it has one sits on the title's own line, and the mark is not a control; and given a folder page, then its mark is a control opening the icon and colour picker, which is the one difference between the two heads and is the one the F3 rework kept.
- AC-258 Given one query that matches a task through a step's title, a folder by name, a shelf by name and a page's own paragraph, then the search overlay draws a result of each of those four kinds, each under its own heading, and the task results keep Q8's Pending, Abandoned and Completed subgrouping inside theirs; and given the overlay opened with nothing typed, then it already offers the places, the pages and the viewer's folders and shelves, as rows that go to them.
- AC-263 Given Important and given Scheduled, then each closes with a collapsed Completed section in the grammar the folder page's already uses; and given a completed task the viewer has starred, then Important's section lists it while a completed task with no star is absent from it, the foot being the page's own work finished rather than every finished thing.
- AC-330 Given a place-page offering more than one view, then every option of the view strip is drawn at rest as a segmented control rather than revealed by a hover; and given Assignments, then its scope strip shows "Everyone" and the viewer's own scope the same way (spec 9.1).
- AC-331 Given the filter's "Custom range" chosen with no day picked, then nothing is narrowed, no chip is drawn and the Filter control counts nothing; and a view saved in that state stores no range (spec 9.1).
- AC-332 Given a view saved from a page's filter panel, then it is listed under "Saved views" in that page's panel and is not filed among the sidebar's pages; and when the filter is cleared, the `?view=` address leaves with it and the filter stays cleared, the window bar drawing no chip for the axis the view had set across the window in which the view's own definition could seed itself back (spec 9.1, 9.7). (The second clause added 2026-09-04 from issue #50, which is #47's larger half: the address was already asserted and the filter was not, so the guard passed over a cleared filter that put itself back half a second later. Like the address clause it can only fail when the race is lost, and neither is a deterministic guard.)
