### 12.8 Views, filters and search

Scheduled, the view queries, the calendar, saved views and the search overlay.
Dana Links resolve through `GET /references/:kind/:id` and are searched through `GET
/references/search`; nothing is stored, a link's durable form being the href a block holds.
Today is 12.7; a folder page's own regions are 12.9.

- AC-052 Given dated tasks including an all-day and a timed task on one date, then Planned lists by date ascending with the all-day row first.
- AC-056 Given 120 completed tasks, then Done pages by 50 using the (completed_at, id) cursor, grouped by completion day in the viewer's timezone.
- AC-057 Given a query matching tasks in accessible and inaccessible folders across all three statuses, then search returns only accessible rows grouped pending, abandoned, completed.
- AC-070 Property: for randomized datasets, All equals Tasks union Planned exactly, the two are disjoint, every non-completed task appears in All, and every completed task appears in Done.
- AC-095 Given Scheduled and Assignments toggled hidden, then the sidebar omits them while their URLs still render the pages (visibility is navigation preference only).
- AC-125 Given GET /views/planned/calendar with end minus start greater than 62 days, then 422 naming the range; given exactly 62 days, then 200.
- AC-126 Given tasks due inside and outside an accepted calendar range in all three statuses, when GET /views/planned/calendar, then real carries exactly the accessible rows due within the inclusive bounds, in all three statuses, ordered all-day banners before timed rows within each date.
- AC-127 Given more than 20 accessible tasks matching a query, then GET /search answers 20 rows with a next_cursor, and the cursor's page carries the rest in Q8's order with no overlap and no gap.
- AC-128 Given a search query that is shorter than 2 or longer than 100 characters after trimming, then 422 naming the field; given 2 and given 100, then 200.
- AC-129 Given more than 1000 rows qualifying for a capped list, then the response carries at most 1000 of them and truncated is true; given fewer, then every row is present and truncated is false.
- AC-130 Given any view endpoint called with a tz that is not a valid IANA identifier, or with no tz at all, then 422 naming the field; given a valid one, then 200.
- AC-131 Given a search query containing a percent, an underscore, or a backslash, then those characters match themselves and the row carrying the literal character is returned while the row that only satisfies the wildcard reading is not.

- AC-156 Given the search overlay of 9.9, then both shortcuts open it, the input debounces at 300 ms, task results keep the Pending, Abandoned and Completed order, enter opens the first result, and no group heading carries a count.
- AC-158 Given an account with no tasks, then each native task view renders the empty-state copy section 6 gives it, an empty folder page retains its compose insertion seam rather than replacing the writable page with task-only copy, the My Day recap is hidden rather than empty, and the calendar shows the bare grid with no message.
- AC-167 Given the View menu on Today, when Show completed is turned on, then today's completed tasks appear in the list checked and muted, and turning it off hides them again, neither change issuing a request (spec 9.1).
- AC-177 Given the Planned calendar's month zoom, then its days are grid cells within a grid, the grid holds six weeks beginning on Monday, and a day holding more rows than its cell renders shows a "+N more" control that reveals the remainder.
- AC-209 Given a page grouped by person in its View menu, when a person's display name changes, then their group still holds their tasks under the new name.
- AC-210 Given a search term matching a page paragraph, a shelf name, and a step title, then each returns under its kind; given a reader consuming only the v1 task results, then its view of the response is unchanged.
- AC-222 Given a filter set on Scheduled, when the viewer navigates away and returns, then it holds; when they visit Today, then Today's filter is independent.
- AC-245 Given Today's "Today" group and Assigned's per-person groups, then each is a named region whose heading is plain text, carrying no count and no collapse control.
- AC-247 Given each of Today, Upcoming and Assigned, then the header is the page's title and a text button "View" on the same line, with no cover, no editable description and no icon-only control, and no "N of M done" count under the title.
- AC-258 Given one query that matches a task through a step's title, a folder by name, a shelf by name and a page's own paragraph, then the search overlay draws a result of each of those four kinds, the task under Tasks, the folder and the paragraph under Pages and the shelf under Collections, and the task results keep Q8's Pending, Abandoned and Completed subgrouping inside theirs; and given the overlay opened with nothing typed, then it already offers up to eight of the viewer's pages in Library order under Pages and "Keyboard shortcuts" under Help, as rows that go to them.
- AC-263 Given Upcoming, when Show completed is on in its View menu, then its dated completed tasks show at the end as a plain "Done" group, checked and muted, and they are hidden again when it is off.
- AC-330 Given a place-page, then its View menu holds at most five items (Layout, Group by, Sort, Label, Show completed), every item a word, a page with more than one layout chooses it under Layout in that menu, and there is no other view or filter control on the page but the chosen label's clear button (spec 9.1).
- AC-1009 Given Assigned or Upcoming with an abandoned task, then the task is not listed while Show completed is off, and with it on the task shows in place struck and muted; Assigned's View menu offers Show completed, which also adds a "Done" group of finished tasks (spec 9.1).
- AC-1010 Given Today holding a started task (its start date has arrived), then it is listed under "In progress" unless it is overdue, when it is under "Carried over"; a task dated later and not started is listed under "Added to Today" when it was pulled in; neither is ever under the "Today" heading (spec 9.1).
- AC-1011 Given the calendar and the list showing the same timed task, then both show its time on the viewer's clock (12- or 24-hour per Settings) (spec 9.1).
- AC-331 Given a filter stored before the View menu replaced the filter panel, then any narrowing the menu cannot show (due range, assignee, creator, important, repeating) is read as neutral, so no hidden filter can hide a row (spec 9.1).
- AC-332 Given a page's View menu choices, then they are kept for that page on return and never carried to another page, under the storage keys they always had (spec 9.1).
- AC-405 Given the Scheduled calendar opened at 9.5's default zoom, when the week zoom is chosen and the page is reloaded, then the calendar is at the week zoom rather than back at month; and when a second browser context signs in to the same account and opens the same calendar, then it is at the week zoom too, the preference following the person rather than the browser; and given the crowded-day reveal of 9.5 pressed instead, then the calendar draws that day but the stored zoom is untouched, so a reload lands on the zoom the person chose and not on `day`, a look not being a choice (spec 9.5, 4.10, 7.23).

- AC-451 Given the four valid Task Schedule states, then Q3 holds every task carrying a Start Date or a Due Date and Q2 holds only the task carrying neither; each task is placed and ordered by its Due Date where it has one and by its Start Date otherwise; the two queries partition the open rows with no gap, no overlap and no task listed twice; a Start-only task whose start has passed still carries no due_date, so nothing derives overdue from it; and the folder page's two open sections and Q4's two blocks split on the same membership, Q4's first block ordering a Start-only row ahead of a starred row due later rather than behind every dated one (spec 6 Q2, Q3, Q4, Q5, Q7, 6.1).
- AC-452 Given the Scheduled calendar and a range, then a task is a real row when its Schedule overlaps that range rather than when its Due Date falls inside it, inclusively at both ends and one day out in each direction excluded; a task whose span crosses the range without either end inside it is present, and present once, carrying both of its dates so the grid draws one continuous bar rather than two events; and a task carrying neither date is never a real row (spec 6 Q3C; AC-126's bounds).

- AC-424 Given a supported Dana URL naming a Task, a Folder or a Shelf the viewer may read, when the reference is resolved, then the answer carries the target's kind, id, display label and canonical internal path and no other metadata; and the path it answers parses back through the shared parser to the target it described.
- AC-425 Given a Dana URL naming a real Task, Folder or Shelf the viewer has no relationship to, then the answer is indistinguishable in status and in body from the answer for an id that names nothing, in both directions between two accounts, and discloses no name, title or other protected metadata.
- AC-426 Given a kind outside the supported set or an id that is not a uuid, then the refusal is the same 404 a missing row answers; and given a malformed `q` or a `folder` that is not an id, then 422 naming the field, while a `folder` the viewer cannot see is 404 like any other inaccessible scope.
- AC-427 Given a contextual search with the current Folder supplied, then that Folder's matching Tasks lead the results without excluding matches elsewhere, every supported kind the viewer can reach is offered, nothing inaccessible appears under either the scoped or the broad call, and the answer is capped rather than a dump of every accessible Task.
- AC-428 Given the same rows offered to both doors, then exact-URL resolution and typed search reach the same verdict about each one in both directions; and given any number of either operation, then no membership, Authority, event or dependency is created by it and a stranger who resolved a target is still refused it afterwards.

- AC-848 Given a member-readable native Purpose facet, then resolving its Dana Link answers `kind: facet`, its stable facet id, the live label (`<Page name> · Purpose`) and `/app/facets/:id`; renaming changes the label without changing id/path and hiding it does not revoke resolution/search; an outsider receives the identical 404 body a missing facet receives; and any number of exact resolutions or picker searches creates no membership, event, Access, Authority or other grant (spec 7.24).

- AC-900 Given a Task referenced by a Dana Link from one Folder page a reader is a member of and from another they are not, when the reader asks what references the Task, then only the first document is answered, with its live name and the id of the block holding the link, and nothing — no name, no id, no count — about the second, while its owner is answered both; a link held in a Task document is answered with `home` `task` only when the reader can open that Task (spec 7.24).
- AC-901 Given a reader who cannot open a Task or a Folder, when they ask what references it, then the answer is the same bare 404 a nonexistent id answers, disclosing no referencing document (spec 7.24, 7.0, 10.2).
- AC-902 Given a referencing Folder renamed after the link was written, then the next "referenced from" read answers the new name, because every label is read live from its own home rather than copied (spec 7.24, #203).
- AC-930 Given a Discussion and one of its Outcomes in a Folder, when a person who is not a member of that Folder resolves either by `GET /references/:kind/:id`, asks for its backlinks, or searches for its title or statement, then every door answers exactly what a nonexistent id answers — 404 with the identical body, no label — or omits it from results, while a member resolves both with the Discussion's title and the Outcome's statement as labels and paths `/app/discussions/:id` and `/app/outcomes/:id` (spec 7.24, 10.2, #320).
- AC-931 Given a Discussion moved to Trash, when even a member resolves it or any of its Outcomes, then both answer 404 as a missing target, and after it is restored both resolve again (spec 7.24, #320).
- AC-932 Given a resolved Discussion whose Outcome is later superseded by a new current Outcome, when the old Outcome's link is resolved, then it still answers that Outcome with its original statement, and the picker offers only the current one (spec 7.24, #320).
- AC-988 Given a document holding Dana Links, when the canvas opens it, then each run whose href is `/app/<kind>/<uuid>` draws as a chip, and saving the document writes the same runs back unchanged, two adjacent links to one target staying two runs (#223, #214).
- AC-989 Given a stored href that is protocol-relative, on another origin, of a kind the client does not know, or not a uuid, then the client draws it as an ordinary link and never as an in-app chip, and a response naming an unknown kind or backlink home is carried rather than failing the read (#223).
- AC-990 Given a person typing `@` at a word start in the canvas, or choosing "Link to…" in the `/` menu, then the picker searches `GET /references/search`, and choosing a row inserts a chip linking to its canonical path whose label is resolved live on every read; a target the reader cannot open or that no longer exists draws as a neutral "Unavailable" chip with no label and no link (#223, spec 7.24).
- AC-991 Given a Task or Folder referenced from documents the reader can open, then its detail shows "Referenced from" and the one document, or a collapsed "Referenced from N places" list naming each document, each opening in-app; with no such document the panel is absent (#214).
- AC-1173 Given a signed-in person, then `GET /settings` answers `focus_lists` as `["today","scheduled","assignments"]` until they change it; a `PATCH /settings` of `focus_lists` stores the keys in the order sent in `user_settings.focus_lists` and a later GET answers them; a key outside Today, Upcoming, Assigned, Important, Overdue, No date and All open is 422 (spec 9.1).
- AC-1174 Given the sidebar, then the Focus heading's "Add a list" menu offers only the Focus lists not shown; choosing Important adds a row that opens `/app/lists/important`, a list of the viewer's starred open tasks with the View menu; a default's "…" offers "Hide" and an added list's "Remove", and a hidden list returns from "Add a list" and stays in its place after a reload (spec 9.1, 9.5).
- AC-1175 Given a page whose Work document holds sections, tasks and blocks, when the Linear view adds a task to a milestone, then the task is stored at the end of that section with every other item kept in order; a task added outside every milestone is stored before the first section, and a task added after a new milestone is stored in that milestone’s section (spec 9.6).
- AC-1230 Given Today holding two tasks wearing the page label "Design" among others, when "Design" is chosen under the View menu's Label, then only those two tasks are listed and a heading whose tasks all left goes too, the choice survives a reload, and pressing "Design" beside View lists every task again; a second label also called "Design" on another page is a separate choice (spec 9.1).
- AC-1231 Given a task in a shared page, when a Can edit member types a new name in its Labels picker and presses Enter, then a label of that page is stored and applied to the task, and "Make "…" just for me" stores a Personal Label applied only in that member's reads; a Can view member is offered neither the page's labels nor "for this page", and their own label is absent from every other member's read of the task (spec 9.3, 7.0).
- AC-1250 Given a Folder's Results tab, when a member writes a native Result, then it is stored as a `result` block of that Results facet, a Result written to Purpose (or any other document) is refused 422 and leaves no row, a member resolves `GET /references/result/:id` with the statement as label and path `/app/results/:id` and finds it in the picker, a non-member gets the bare 404 and never finds it, and a Duplicate of the Folder has an empty Results tab (spec 7.24, 10.2, #213).
