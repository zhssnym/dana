### 12.22 The public surface: landing, legal, install, offline

What a signed-out browser is served: the landing page, the legal pages, the manifest, the
offline shell, and the mark.

- AC-091 Given one prior online load, when the installed app opens offline, then the shell renders with the offline banner and a write attempt shows the failure toast with nothing queued.
- AC-100 Given a new build is deployed mid-session, then the reload affordance appears and no forced reload occurs.
- AC-159 Given the landing page at /, then it describes the shipping product with one "Continue with Google" button and privacy and terms links, and makes no AI claim anywhere.
- AC-160 Given a prior online load, then every /app path falls back to the cached shell offline while / does not.
- AC-163 Given the installed application's manifest, then it names Dana, displays standalone, starts at /app, and carries fetchable 192 and 512 icons with a theme and a background color.
- AC-240 Given no session, when `/privacy` and `/terms` are visited, then each renders its own page, headed by its title and carrying the copy DES-032 approved, rather than the not-found copy of 9.1; and the Privacy and Terms links 9.2 puts in the landing footer resolve to those two pages.
- AC-265 Given the landing page, then every place Dana's mark appears is an inline `<svg>` drawn in the document rather than an `<img>` fetching `/dana-mark.svg`, that file staying where it is for the favicon, the manifest icon and the transactional emails; and given the three marks that page draws, then each carries a mask of its own with no two ids alike, so no mark can take another's; and given no pointer has touched them, then each is already fully drawn at rest, its sweep at zero offset, so a mark that never animates, or animates with scripting off, is simply the logo; and given the sidebar signed in, then its mark is drawn the same way and the link it sits in still reaches Desk under its own accessible name; and given a viewer whose system asks for reduced motion, then hovering the control a mark sits in starts no animation on it.

**What AC-265 asserts is what a browser can observe, and the ledger's sharpest clause is
deliberately not.** L-142's mask uncovers 100.00% of the mark's 62,385 pixels, which is a
rasterisation the prototype's own header records and which no browser assertion can reach;
asserting a pixel count would pin the criterion to a geometry file rather than to a behaviour.
What the browser sees instead is the shape of the decision: an inline `<svg>` where an `<img>`
used to be (L-141), a mask id that is this instance's own (L-144), a rest state already fully
drawn (L-143), and an animation that does not start when the operating system says not to
(L-145).

**The landing page is the surface because it draws three marks, not one.** It carries the
header lockup, the closing block's mark and the footer lockup, so L-144's clause has three
instances on one document to be distinct across, which is the failure it exists to catch: the
second mark silently steals the first one's mask and the logo it belongs to disappears. A
criterion reading one mark could never see it.

**`public/dana-mark.svg` is asserted to survive, not to disappear.** A favicon, a manifest
icon and a real transactional email all point at that file, so the criterion asserts that no
`<img>` fetches it on a page that draws the mark, and asserts nothing about the file itself.
An implementation that deleted it would pass this criterion and break three things it does not
measure.
