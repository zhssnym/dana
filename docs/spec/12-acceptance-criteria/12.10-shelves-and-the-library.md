### 12.10 Shelves and the Library

Shelves as rows and as pages, and the sidebar block that lists them. Moving a folder by dragging is 12.19.

- AC-180 Given the sidebar's folder list, then a folder group can be created by naming it, renamed and deleted, and a folder moved between groups or out of every group; and deleting a group keeps every folder that carried it and every task in them, in the ungrouped list.
- AC-203 Given shelves, then (user_id, name) is unique; renaming keeps the shelf's id and its page; deleting clears the member labels and keeps every folder.
- AC-223 Given a shelf page, when a folder row is pressed, then the folder opens as its own tab beside the shelf's; when Add folder places an existing folder, then it joins the page without a reload.
- AC-257 Given a shelf created through 7.16, then after a full reload the Library lists it as a group headed by its name linking to the shelf's page, the tab strip's "New tab" menu offers it beside the folders, and an empty shelf is listed too.
- AC-313 Given "New shelf", when a name is typed into "Shelf name" and "Create shelf" pressed with no folder ticked, then the shelf exists as an empty region of the Library named by it, and the dialog says "shelf" and never "group" (spec 9.1, 7.16).
- AC-334 Given a person with shelves, when a folder page's "Move to shelf" is opened, then it lists the shelves by name with "Not on a shelf" as the way off, choosing one moves the folder with an undo bar, and the dialog calls it a shelf throughout (spec 9.1, 9.10, 7.16).
- AC-366 Given one person's shelf, when another person asks for it by id, then GET /shelves/:id, GET and PUT /shelves/:id/page, PATCH /shelves/:id and DELETE /shelves/:id all answer 404, never 403, and no refusal discloses the shelf's name (spec 4.18, 7.0, 7.16, 10.2).
- AC-367 Given a folder carrying a personal label, then that label names a shelf the viewer can open: writing a label through 7.4 makes its shelf in the same transaction, every stored label has one, and clearing a label leaves the shelf standing (spec 4.4, 4.18, 7.4, 7.16, 9.1, 9.10).
- AC-368 Given a shelf, when its owner sets a cover through PATCH /shelves/:id, then the shelf wears it on later reads; a file and a preset are one source, each clearing the other; the crop stores and moves on its own; and clearing both leaves no cover (spec 4.18, 7.16).
- AC-369 Given a shelf, when its owner names a cover they cannot reach, one that is not a picture, a uuid naming nothing, or a file and a preset at once, then 422 with one sentence for every unreachable case and the shelf unchanged; and POST /shelves carrying a cover is 422 (spec 4.18, 7.16, 10.2, 11.14).
- AC-387 Given a shelf wearing an uploaded picture, when POST /shelves/:id/duplicate is called, then 201 with a new shelf carrying icon, colour, description and crop, named "(copy)" then "(copy 2)" as 4.18's uniqueness forces, and a `cover_file_id` of its own with the same bytes serving 200; taking either cover off leaves the other drawing; a preset duplicates as a key with no file; and another person's shelf is 404 (spec 4.18, 7.15, 7.16, 10.2).
- AC-388 Given a shelf or folder duplicate whose object write fails, before or after the bytes land, then 500 with no new shelf or folder, no copied files row and no object left in the store, the source still drawing its picture; and once the store answers again the same call succeeds (spec 4.16, 7.16, 11.10).
- AC-407 Given a shelf wearing an uploaded picture, when Duplicate is pressed in its More actions, then exactly one call is sent, the copy named "<name> (copy)" opens drawing the same picture from its own file id, and taking the copy's cover off from the band leaves the original drawing its picture and that file still served (spec 4.18, 7.15, 7.16, 7.19, 9.10).
