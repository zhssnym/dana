### 12.18 The application shell

The sidebar, the account menu, the confirmations, and the phone layout.
What a page draws inside the shell is 12.8 and 12.9.

- AC-155 Given folders on and off shelves, then the Library lists Desk first with no count, then the viewer's shelves and folders in the viewer's order, and no folder row draws a pending count (spec 9.1).
- AC-162 Given each destructive action section 9 puts a confirm on, then the confirm carries that section's copy, offered as "Continue" and "Cancel", and declining it performs nothing.
- AC-171 Given a page whose read fails, then it renders 9.1's inline copy with the "Try again" control beside the thing that failed and the control refetches; given a read that answers 404, then it renders the not-found copy instead of the error state.
- AC-174 Given the application shell, then the sidebar is a navigation landmark carrying the "Account" button, the "Notifications" bell and the "Search" field, draws no logo, and no chrome exists above or outside it; and no tab strip or "New tab" control exists anywhere (spec 9.1).
- AC-175 Given the three page entries and each folder row in the sidebar, then each is a link whose destination is that surface's path in 9.1's routes table, and the entry for the current page is marked as current.
- AC-182 Given the sidebar collapsed or resized, and given the task form resized, then each state survives a reload of the page; and the collapsed sidebar is fully hidden and inert, with "Expand sidebar" at the page's top left and Ctrl+B / Cmd+B bringing it back (spec 9.1).
- AC-183 Given each of section 9's normative strings that the designer's prototype omitted, split or reworded, then the built client renders each as one text run, character for character as its section writes it: 9.1's failed-read line and 404 line, 9.3's steps cap notice, 9.4's abandon confirm, 9.6's leave and remove-member confirms, 9.8's already-connected refusal and remove-connection confirm, and 9.1's member exit label.
- AC-214 Given the sidebar, then from the top it carries a head row of "Account", "Notifications" and "Collapse sidebar", then the "Search" field, then Today, Upcoming (/app/scheduled) and Assigned (/app/assignments) as links in that order, then the Library heading, with no Desk, All, Important, Anytime, Done or Abandoned entry, no "More" row and no saved view (spec 9.1).
- AC-215 Given /app/planned, then the browser lands on /app/scheduled; given /app/tasks, /app/all, /app/anytime, /app/important, /app/done or /app/abandoned, then it lands on /app/today, each replacing the history entry rather than adding one; given /app, then it lands on /app/today; and given /app/desk, then it lands on the default folder's page at /app/folders/<id> (spec 9.1).
- AC-216 Given a page, when a sidebar link, a folder row or a search result is chosen, then the router goes there and no tab, tab strip or tab close control is drawn (spec 9.1).
- AC-242 Given the account menu, then it names the viewer (name and email) and carries, in order, Settings and Sign out, with no Import, no Help and no People; Settings reaches its page when chosen, and /app/people still answers (spec 9.1).
- AC-264 Given the sidebar, then its footer carries the "Settings" and "Trash" links and nothing else, and the Library heading carries one "+" named "New", resting visible, whose menu is exactly "New folder", "New collection" and "Import workflow…", the first of which opens the dialog that makes one (spec 9.1).
- AC-310 Given the application at a phone width (390 by 844), then a bar offers "Menu" and "Search" and nothing else; when Menu is pressed, then the sidebar opens as a drawer holding the head row with the "Notifications" bell and the page links but no Search field; when a page link in it is pressed, then the page opens and the drawer closes; when Escape is pressed, then it closes; and when a task is opened, then its surface fits the phone's width with "Close task" on screen (spec 9.1, 9.3).
- AC-312 Given any width, then no floating "Add task" button renders on any page; and given a phone width, then Today, Upcoming and Assigned keep their "New task" row pinned to the bottom of the screen while the list scrolls (spec 9.1).
- AC-338 Given the sidebar, then no "More" row or disclosure exists (spec 9.1).
- AC-401 Given a folder row and a shelf heading, when either is right-clicked, then the menu that opens is the same as its "More actions" menu; and given a folder row, then "More actions" appears on hover without shifting the name and is always visible on touch (spec 9.1).
