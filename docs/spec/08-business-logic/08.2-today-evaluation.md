### 8.2 Today evaluation

```
def my_day(V, tz):
    today = current_date(tz)
    # activation: the day the Schedule begins (issue #217; was due_date alone)
    activation = coalesce(start_date, due_date)
    open_rows = tasks where folder_id in ACCESSIBLE(V)
                and status = 'pending'
                and ( (assignee_id = V and activation is not null and activation <= today)
                      or exists my_day_entry(task, V) )
    for t in open_rows:
        auto_q  = t.activation if (t.assignee_id = V and t.activation <= today) else None
        pull_q  = entry.added_on if entry exists else None
        t.qualify_date = min(x for x in [auto_q, pull_q] if x is not None)
    carried = rows where qualify_date < today   # ordered per Q1
    today_g = rows where qualify_date = today
    recap   = Q1R rows
    return carried, today_g, recap
```

Consequences, each intended: nothing ever leaves this page by time passing (snowball); a
pull is one decision, not a daily ritual; pulling a future or someone else's task shows it
with its assignee chip; completing from anywhere surfaces it in the recap; abandoning
removes it from the open groups instantly and keeps it out of the recap.

**The automatic date became the activation date on 2026-09-20 (issue #217), and the
clause moved rather than gaining a second arm.** That is the whole of the change and it
is deliberate: auto_q is "the date the automatic clause held on", so an OR of a due
clause and a start clause would give one row two candidate dates and two answers to
which group it lands in. Four things follow, all of them this page's existing rules
applied to a date that moved. A task starting today and due in ten days is in **Today**
on the day it starts. On the days after, its auto_q is still that start date, so it is in
**Carried** - which is this page's word for work that began before today and is not
finished, not a word about lateness; overdue stays 8.1's relation to the deadline. A
Start-only task behaves the same way and never becomes overdue at all. And a task
carrying neither date still never qualifies automatically, because the clause holds on a
date the task carries and age is not one.
