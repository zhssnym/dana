### 8.8 Folder deletion and member removal

Folder deletion (owner only, never the default folder), one transaction: count open,
completed, abandoned tasks for the confirmation response; set the folder's deleted_at,
which is 7.13's soft delete. The folder leaves every member's sidebar and every query but
the Trash surface at once, and nothing cascades yet. Inside the 30-day window anyone with
access to the folder may restore it, not only whoever deleted it, and it returns with its
membership intact (9.11).

The cascade belongs to the purge, and the purge is 11.7's tick duty: at 30 days the folder
row is deleted, and the database cascades memberships, tasks, and through tasks the steps,
my_day_entries, and reminders; pending invites carrying the folder cascade away; and the
same pass collects the files rows those deletes will cascade away and removes their
objects from the store after the delete commits, because those rows are the only index to
the bytes. Only from that moment is nothing recoverable, and the dialog says so with its
counts and with the window.

Account deletion is not this path. 8.10 deletes an owned folder's row outright, taking the
purge's cascades in the account's own transaction, because an account that no longer
exists cannot reach a Trash.

Member removal and leave both run R-CLEAN of 5.3 (`runRClean` in
`app/src/server/domain/folders.ts`): end the leaver's Responsibility standing (8.10),
permanently delete the leaver's **private** facets in the folder with their `page_blocks`,
unassign the leaver's tasks in the folder, delete the leaver's Today entries for the
folder's tasks, delete the membership, and, when exactly one member remains, assign every
unassigned task in the folder to that member (INV-5). Removal never deletes a task: it
only unassigns.

A private facet is writing no other member may ever read, so once its owner leaves it would
be readable, removable and restorable by nobody. **Shared facets are Folder data and are
untouched**, the same distinction drawn for Tasks: the leaver's work is unassigned rather
than deleted. 4.30 carries the reasoning.
