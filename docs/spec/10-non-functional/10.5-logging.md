### 10.5 Logging

Logged: database connections lost from the pool, authentication events, invite lifecycle
transitions (invite id, not the email address), folder deletion and account deletion with
row counts, status transitions (task id, actor id), reminder sends and skips, data exports
(user id and byte count), CSP violation reports, request bodies carrying undeclared fields,
pictures the reclaim sweep deletes, scheduler passes that did something, and request errors
with status codes. Never logged: task titles, notes, step titles, file names, email bodies,
OAuth tokens, session identifiers, or any value a caller sent. Retention 30 days. No
analytics or tracking.

**The list above is an enumeration, not an illustration.** A new act that writes a log line
is added to it, or it is not logged. The event names and the logger are in
`app/src/server/security/log.ts`; where a line's fields are fixed below, the fixed set is the
whole set, and the logger has no parameter through which anything else could arrive.

- **Data export**: who exported and how many bytes left. The size is how anyone would notice
  the endpoint outgrowing an in-memory build; it says nothing about content.
- **`csp_violation`** (warn): the effective directive, the blocked URI reduced to its scheme
  and host or a bare CSP keyword, and the document path without its query string. A report's
  `script-sample` is page content and its query string can be whatever someone typed into a
  search, so **neither may ever be logged**. A report 10.8's filters drop writes nothing.
- **`unknown_request_fields`** (warn): the route as method plus mounted path template, never
  the concrete URL, and the names of the undeclared top-level keys, capped, beside a count of
  distinct keys taken **before** the names are whitelisted (whitelisting first would collapse
  many ill-formed keys into one and erase the magnitude). Key names are whitelisted to the
  snake_case shape `app/src/shared/` uses and anything else is written `other`, because a
  caller chooses the names and an OAuth token is a legal JSON key. No value is ever logged. A
  fully declared body, or one refused 422, writes nothing. One line per offending request, no
  dedupe: a second caller sending the same key is exactly what the line exists to show.
- **`database_connection_lost`** (warn): the driver's code and the connection's own message,
  both through the logger's whitelists. Warn rather than error because the pool replaces the
  connection itself; the line exists so a pool losing connections does not look healthy. One
  line per lost connection, not one per query that failed with it
  (`app/src/server/observability/connection-lost.ts`).
- **`file_reclaimed`** (info), one per picture the 11.7 sweep deletes: the file id, owner,
  kind, byte count and the `unreferenced_since` mark. The sweep is the only act in Dana that
  destroys a person's data on a clock rather than a request, the referencing rows cascade
  away with the file, and a folder-less file has no 4.13 event to record it, so without this
  line nothing would show it had happened. The file name is user content and is never on it.
- **`reminder_pass_completed`** (info): the sweep counts and the pass duration, written only
  when a count is non-zero or the pass took longer than half a tick, so a real line is not
  lost among zeroes and a slow pass is flagged before `reminder_pass_overlapped` fires.
  Delivery counts are absent because each send, skip and refusal already writes its own.
