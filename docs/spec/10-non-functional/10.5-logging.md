### 10.5 Logging

Logged: authentication events, invite lifecycle transitions (invite id, not the email
address), folder deletion and account deletion with row counts, status transitions (task
id, actor id), reminder sends and skips, data exports (user id and byte count), request
errors with status codes. Never logged:
task titles, notes, step titles, email bodies, OAuth tokens, session identifiers.
Retention 30 days. No analytics or tracking in v1.

**The data export entry was added 2026-09-04 with 7.22 (issue #77).** The sentence above
is an enumeration rather than an illustration, so a new act that writes a log line is
added to it or it is not logged. Two fields and deliberately no third: who exported, and
how many bytes left. The size is the one thing worth knowing after the fact, being how
anyone would notice the endpoint outgrowing what building a document in memory can carry,
and it says nothing whatever about what was in it — which is what the "never logged" list
requires of a surface that touches every table a person's content lives in.

Added 2026-09-04 (issue #99): a Content-Security-Policy violation report reaching 10.8's
endpoint writes one warn-level `csp_violation` line carrying **three fields and no
fourth** — the effective directive, the blocked URI reduced to its scheme and host (or
the bare CSP keyword, `inline` and `eval` being the two that name Dana's own defects),
and the document's path with the query string removed. The exclusions are the point and
are why the whitelist is written here rather than left to the endpoint. A report carries
`script-sample`, which is a slice of the source that was refused and is therefore page
content, and its `document-uri` carries a query string, which on a search URL is whatever
someone typed; **neither may ever be logged**, and the logger has no parameter through
which either could arrive. A report from an origin that is not this deployment's, or one
this section's filters drop, writes nothing at all.

Added 2026-09-04 (issue #104): a request whose JSON body carries a top-level key its
schema does not declare writes one warn-level `unknown_request_fields` line carrying
**two fields and no third** — the route as its method and mounted path template, never
the concrete URL, and the names of the undeclared keys, at most twenty of them beside a
count of how many there were. **No value the caller sent may ever appear**, which is what
makes this line admissible at all: it exists to end the silence 11.14 records around
7.0's tolerance of unknown fields, and it would be worth nothing if ending that silence
meant putting a task title in the log. The key *names* are the one part a caller chooses,
so they are whitelisted to the snake_case shape `app/src/shared/` writes and anything
else is written as `other`; an OAuth token is a legal JSON key, and AC-103 refused the
first draft of this line for admitting one. A body every key of which is declared, and a
body that failed validation and was answered 422 with its fields named, both write
nothing.
