### 9.5 Scheduled and Assignments

- **Scheduled**: everything carrying a Schedule — a Start Date, a Due Date, or both. A row
  is placed by its Due Date where it has one and by its Start Date otherwise, while the row
  itself shows the whole Schedule; a Start Date passing is not overdue and is never styled
  as one. The list is Q3's order under a ladder of headings — Today, Tomorrow, the days of
  this week, then week and month rungs — headings being structure, not controls; a row
  says "Due tomorrow" about one task and a heading "Tomorrow" about a bucket. Two rungs name
  a relation to today rather than a day and take no capture, having no date to write:
  **Overdue**, and **Started** for a Start-only task whose Start Date has passed, which
  leads the list by date but is not late — calling it Overdue would be the forbidden
  overdue styling written as a word. One function (`app/src/client/views/ladder.ts`) draws
  every rung for the list and a date-grouped board, so a row is never filed under two
  headings on one page.
- **Scheduled's calendar** (`app/src/client/components/calendar/`): Q3C whole — day, week and month
  zooms; Monday start; all-day before timed; repeating ghosts carry the banner "Upcoming
  occurrence of a repeating task"; an empty cell creates with that date. A Due-only task is
  a one-day event, a Start-only task a one-day start event, a same-day pair one event, and
  a pair on different days one continuous bar from Start through Due, split into connected
  weekly segments and dragged whole. "+N more" opens that day at the day zoom for as long
  as the person is on the page and never writes the stored zoom: looking is not choosing,
  and a side-effect write would carry to every device. Zoom persists on the account as
  4.10's `calendar_zoom` through the settings bundle, with a browser mirror for the first
  frame only (`app/src/client/lib/calendar-zoom.ts`); the view mode stays a client-side preference reached
  by `?mode=`.
- **Assignments**: who is carrying what — every open task the viewer can read, grouped by
  person, the viewer's own group first, "Unassigned" last. The "from" half of a row names
  the creator; Dana records no assigner. On the board, dropping a card on a person assigns
  them; capture assigns the viewer. A whose-assignments scope control in the window bar
  rests on everyone; the sidebar entry's name never changes, the value living in that
  control.

Completing is immediate on the wire: no write is held back. The undo bar of 9.1 takes a
completion back by issuing the inverse transition as a new mutation — the same "Mark as not
done" a person could press on the completed row, offered for five seconds where they stand.
