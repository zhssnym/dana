### 9.3 The task (create and edit are one artifact, and the artifact is the task)

There is no task form. A task is its row and its page. Clicking a task anywhere (a list
row, a task in a page's thread, the calendar, search, a dependency link) opens its one page,
/app/tasks/:id, inside the app's shell and sidebar, on a desktop and a phone alike. There is
no peek and no setting for how a task opens: one route, one presentation, and Back returns to
where the task was opened, the thread restored to the same place. A sub-page (a page
block, a sidebar row) is a place and navigates the same way. Every edit commits as it is
made — no Save control, no draft state — and 9.1's undo bar covers the destructive ones. An
unsaved task has no page: a task is made inline and then opened.

The page is `app/src/client/components/task-card.tsx`, one column: the title (large, renamed
in place), then one properties block, then the task's document (the Task composer, where the
checkbox is a subtask: `/` Checklist or `[]` + space turns the line into one of the task's
subtasks, or on an empty line opens "Type a subtask", and a pasted checklist joins the
subtasks in order, ticks kept, nested items flattened, while its other writing stays; over
the 50-subtask cap it stays as pasted), then **the task's history**, collapsed by default
and expandable: its events (created,
done, dropped, reopened, reassigned, date moved, marked blocked by or as blocking), oldest
first, and no posts. **The document holds only what the person wrote**: an act on the task
records itself in the history and never writes into the body. `/Blocked by` opens the
dependency picker by the properties, clears its slash text (and the line, when that text
was all it held), and writes no block. The history
ends in "Discuss" and one "Mark done ▾" whose menu holds Drop, or "Reopen" once the task is
finished. The task's creation and completion from 4.13 (actor, viewer-local time, "Deleted
user" fallback) are events in that history.

**Talk about a task lives in its page's Discussion (9.6), never on the task.** "Discuss"
(Can comment and above) opens the task's one Discussion (`POST /tasks/:id/discussion`, 7.28),
making it on first use, titled as the task. Once someone has written in it, "Discuss" is
replaced by one quiet link, "Open the discussion", with no count; until then a thread only
opened and left (no post, no input round) is neither listed nor linked. A Desk task,
whose page has no Discussion tab, is not offered "Discuss"; one whose old comments
migration 0059 moved into a thread shows the same "Open the discussion" link, and closing
that thread returns to Desk's Work.
The page draws no participants list and no "Referenced from".

The properties block is a FIXED set of quiet rows — Status first, then Date and Assignee,
each but Status shown only when set — plus one "Add property" menu that offers the unset ones
and, behind it, Waits on, Repeat, Reminder and Subtasks, each revealed already
asking its question and shown afterwards only when set. A task with a dependency draws
"Blocked by" and "Blocks" as property-like lines under the properties, one far task per
line, each opening its task and removable there. There are no custom properties.
Labels are not offered or drawn anywhere; a task's stored labels stay in the data.
**Status** is To do, Done or Dropped: Done is 7.6's complete, Dropped is its abandon (the
stored value stays `abandoned`), and any other choice from Dropped restores the task. A
dropped task never draws the done check. Nothing else on the page is dragged or collapsed. The
page's one "More actions" menu holds Copy link, Duplicate and Delete task; finishing is the
timeline's and the Status row's, and the breadcrumb names the page the task lives in, so
neither is repeated there. A task is moved from its row's "More actions". A task's files
live in its document (file and image blocks); files posted in its Discussion stay there.
Pickers open on the answer, not the instrument — resolved presets
first, a calendar or list behind them.

Field rules (limits and their messages: `app/src/shared/tasks.ts`,
`app/src/client/components/task-copy.ts`; a refused value answers 422 with the field
named):

- **Title** is required; an empty commit is refused, not saved.
- **Due date** is a day, with an optional time. The due picker's Time field sets and
  clears 4.11's due_time, the time the Date row shows. A reminder the time change would
  make illegal under 8.4 is rewritten in the same PATCH in the task's new mode, at the
  clock time it had (moved to the due time if it would fall after it; removed if it was on
  the day before and the time is cleared), and the picker says so.
- **The Date row is the Schedule**: a Start Date, a Due Date, both, or neither. Its picker
  switches between **Due** and **Starts**; presets, the grid and Clear answer for the end
  chosen, and the grid shades the span. A start after the due date (or a due date before
  the start) is refused in the picker with "The start must be on or before the due date."
  and neither end moves. Clearing the start cascades nothing. The row reads "Starts 24 Sep",
  "24 Sep – 30 Sep", or the due date alone (a same-day pair is one day); overdue is the due
  date's alone. A task not yet created takes only a due date.
- **Reminder** and **repeat** require a due date: "Add property" offers them only once the
  task has one.
- **Repeat** is preset-driven (daily, weekdays, weekly on chosen days, every N days,
  weeks, months or years, monthly on day 1 to 28, yearly, optional end date); never a raw
  RRULE box. Each choice writes `recurrence_rule` at once; an end date already on the
  stored rule is kept.
- **Reminder** words its day as the Date row does ("Sat 6:00 PM"). On a timed task it
  offers "At due time", "1 hour before" and "Day before", the last being the same clock
  time on the previous day, each with when it lands beside it.
- **Assignee** offers the target folder's members, "Invite by email", and "Unassigned"
  last after a separator; hidden in single-member folders (INV-5).
- **Subtasks** are the checklist items of the task's body, written like any other block
  (`/Checklist` or `[] `); there is no separate list. Assigned work on its own task sees
  the body read-only and may tick its checklist.

Clearing the date keeps 8.4's warning verbatim, and moving a task warns when an assignee
would be unassigned (words: `app/src/client/components/task-copy.ts`). "Delete task" moves the task to Trash at once, with no confirmation, and offers the undo bar; a task's block menu on a page does the same.

Rows (`app/src/client/components/task-row.tsx`):

- A row carries its section after its folder chip, read as a path, and omits it where the
  row already sits under that section's heading.
- A row is one line, 32–36px: checkbox, title, then muted meta on the right (date,
  or the Schedule as "Starts Mon" / "24 Sep – 30 Sep", both ends as dates, folder only where the list spans folders, assignee face, repeat glyph; no counts) and
  the star, drawn on hover and whenever it is set. The meta is text, not controls.
- One model turns a task's fields into words for row and card alike
  (`app/src/client/tasks/task-model.ts`). Wherever a person is drawn, their own uploaded
  picture (7.15) is drawn; otherwise their default face, a small drawn character chosen
  deterministically from their name, so one person looks the same everywhere. The account
  picture stored from Google stays stored but is not drawn, and no surface draws initials.
- Pressing anywhere on a row opens the task; the checkbox and the star are the row's only
  controls. There is no chevron, no row overflow menu and no rename in the row: the task's
  page carries its title and its one "…" menu. Shift-click or Cmd/Ctrl-click selects
  rows, and a selection shows a bar whose acts are words: Complete, Move, Date, Delete,
  Clear. On a touch screen the star is an indicator only, never a tap target.
- An empty block draws the control that fills it rather than nothing.

Entry defaults, derived from the page's own spine so a made task appears where it was made:

| Opened from | defaults |
| - | - |
| Today | folder Desk, a Today entry (membership), dated today |
| Upcoming's list | folder Desk, dated tomorrow |
| A calendar cell (its inline "New task" line) | folder Desk, dated that cell's day |
| Assignments | folder Desk, assigned to the viewer |
| A page's thread, its last line | that folder, the section it ends; on a phone, the section in view |
