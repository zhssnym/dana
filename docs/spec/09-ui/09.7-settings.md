### 9.7 Settings

The page (`app/src/client/components/settings-page-content.tsx`) is one column at the page
measure, left-aligned under a plain title, the same frame Trash wears
(`components/settings/screen.tsx`). Each section is a small muted label above one rounded,
bordered card whose rows are split by the one hairline. Every row is a label with its control
at the far end, on one line on a phone too (a long description wraps instead), and the
pickers share one width. Settings is the home of every configuration:
a preference is chosen here and not also toggled from a menu elsewhere. The page is
reached from the sidebar footer's "Settings" row (9.1). Every picker is the
one custom `Combobox` (`components/ui/combobox.tsx`), never a native select; a list longer
than ten filters as you type.

Sections, each a named region, in this order (Account, Preferences, People, Data):

- **Account** — the Google identity (picture, name, and "email · from Google"), shown as read from Google; profile picture upload
  (7.15), the picture itself being the control and showing the default face until one is
  uploaded, with "Remove picture" offered exactly while there is an uploaded picture. The same
  identity row carries the "Sign out" button, which ends the session. This is Sign out's one home (9.1).
- **Preferences** — theme (system, light, dark). The theme is applied to the document before
  first paint from a copy mirrored into the browser, so a reload never flashes; 4.19's
  column stays the record, the mirror is written wherever the bundle is read or written,
  `system` mirrors as `system`, and sign-out clears it (`app/src/client/lib/theme.ts`).
  Then a timezone the viewer chooses, through 7.1's PATCH /me, detected on the first
  session, picked from a searchable list; and the clock (12- or 24-hour).
- **People** — 9.8's roster and bare invites (`components/settings/people.tsx`), anchored
  at `#people`; /app/people redirects to /app/settings#people.
- **Data** — "Download my data", 7.22's export. The download is an anchor to GET
  /api/v1/me/export carrying the `download` attribute, not a fetch: a navigation carries the
  session cookie and hands 7.22's `Content-Disposition: attachment` to the browser, which
  saves the file under the server's name. The known cost is that the endpoint's rate-limit
  refusal arrives as a downloaded response rather than through 9.1's toast. Then:

  - **Sample workspace** — one row, drawn once the client knows whether 7.20's sample workspace is
  present, described as "A sample workspace to show you around." (no count), offering Remove,
  or "Add sample pages" when it is absent (the client cannot tell removed from never had, so
  the label is neutral). Remove asks first ("Remove the sample workspace?"), then offers the
  undo bar, whose inverse is POST /sample. This row is removal's one home.
After the sections, in a card of its own, is **Delete account**; under it, as the
very last line, a quiet line carries the support address. Every row is the system `Row`
(`components/ui/row.tsx`); every control is the
one control height, ordinary actions are neutral buttons, and Delete account is the one
danger button, its confirm's action ("Delete account") in the same hairline danger style.
The page fits one desktop screen, and its controls wear only the app's one focus outline.

  - **Delete account** — shows its consequences, requires typing DELETE, and says that shared pages the
  viewer owns must first be handed to another member or deleted (Dana names which) and that
  private pages and their tasks are permanently deleted; this matches `DELETE /me`, which
  answers 409 naming every owned shared folder until each is transferred or deleted.

There are no view-pin switches (the sidebar has no pinnable views), and no row density
choice: rows are one line. There is no "Open tasks in": a task always opens as its one page
(9.3).

Trash is reached from the sidebar footer (9.1), not from this page.
