### 9.9 Search overlay

Opened by 9.1's "Search" control, Ctrl+K / Cmd+K, or "/", and Ctrl+K again closes it; the overlay is a dialog named "Search
Dana" (`app/src/client/components/search-overlay.tsx`). Input is debounced. Before
anything is typed it offers up to eight of the viewer's pages, the Desk first and then Library order, under Pages,
and "Keyboard shortcuts" under Help; as the viewer types, Today, Upcoming and Assigned are
matched by name too. Any typed character filters: below the search's
two-character floor, the places and the pages and collections already in hand are matched by
the start of a word in their names.

Results group by kind, each group under a plain sentence-case heading in small text with
no count: Tasks (title, notes, step titles), Pages (a
folder's name and description, and a page's own prose; a folder is a page on screen and wears
its chosen glyph or the plain page glyph, never a folder; a page's own prose wears the text
glyph, since it is a passage and not a page called that) and Collections (name and
description). A task wears the task glyph. A page result's second line is its
place in the page tree, "Root / … / Parent" in muted text, as the viewer may see it, and a root page
or a collection has none; a passage's reads "in" the page it is on, and opening it scrolls that page
to the passage. Among task results of equal rank Q8's Pending, Abandoned, Completed order holds,
each row wearing its status as muted text rather than standing under a
status heading, since two classification schemes as peers is a fault; Pending is announced
but wears no visible status, a word saying "ordinary" on nearly every row saying nothing. Within a kind the better
match leads: a name that is what was typed, then a name or a word in it that starts with it,
then a name that contains it, then anything else, a passage always last. The kind whose first
row matches best stands first, a page or collection before tasks on a tie, so Enter reaches the
thing named what was typed before a task that only mentions it; Help stays last. The arrows
move the cursor and keep it in sight, and Tab moves it too; the arrows still work from a row Tab
reached. A new answer puts the cursor on its first row with the list at its top. Enter opens
the cursor's row, and Enter pressed before the answer for what was typed arrives waits for
that answer; a row opens its thing in
place. A row carries no arrow. There is no footer and no close button: Escape or a press
on the scrim closes it. On a phone the overlay fills the screen, and a "Cancel" button at the
end of the field is the way out, a phone having no Escape and no scrim. While the next answer
is on its way the last one stays on screen; a skeleton shows only when there is nothing yet.
