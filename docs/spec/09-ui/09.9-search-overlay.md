### 9.9 Search overlay

Opened by 9.1's "Search" control, Ctrl+K / Cmd+K, or "/"; the overlay is a dialog named "Search
Dana" (`app/src/client/components/search-overlay.tsx`). Input is debounced. Before
anything is typed it offers exactly Today, Upcoming and Assigned as rows to go to, with no
descriptions — every folder and shelf would be the sidebar drawn twice — and as the viewer
types, those are matched by name too. Any typed character filters: below the search's
two-character floor, the places and the pages and collections already in hand are matched by
the start of a word in their names.

Results group by kind, each group under a plain sentence-case heading in small text: Tasks (title, notes, step titles), Pages (a
folder's name and description, and a page's own prose; a folder is a page on screen and wears
its chosen glyph or the plain page glyph, never a folder) and Collections (name and
description). A task wears the task glyph. A page result's second line is its
place in the page tree, "Root / … / Parent" in muted text, as the viewer may see it. Task results keep Q8's Pending, Abandoned,
Completed order, each row wearing its status as muted text rather than standing under a
status heading, since two classification schemes as peers is a fault; Pending is announced
but wears no visible status, a word saying "ordinary" on nearly every row saying nothing. Within a kind a title
match ranks above a body match. Enter opens the first result; a row opens its thing in
place. The footer shows key hints and nothing else, and is not drawn on a phone, which has no
keys to hint at. A row carries no arrow. The overlay has one close control;
Escape is a hint, not a button.
