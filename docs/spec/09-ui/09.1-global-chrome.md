### 9.1 Global chrome

The shell is `app/src/client/shell/` (`app/src/client/shell/app-shell.tsx`, `app/src/client/shell/app-sidebar.tsx`, `app/src/client/shell/TabStrip.tsx`);
what each part draws is there. The rules it is held to:

- **Sidebar.** The navigation landmark and the application's only side chrome. Its page
  block is in fixed order — Today, Scheduled, Assignments, then any saved view the pin
  list of 9.7 has pinned — each a link, and a page the pin list has unpinned is not drawn.
  Then the Library, whose first row is Desk, then the footer.
- **Library.** The viewer's shelves and folders as one ordered list, Desk first;
  the rest of the order is the viewer's own, seeded alphabetically
  and rearranged by dragging (rows reorder, move onto and off shelves, two folders held
  together make a shelf, shelf headings drag as rows). A closed group is never sprung open
  by a drag hovering it; the drop reads "Into {shelf}".
  The heading's "New" control begins New folder, New shelf or New task, and rests visible
  rather than revealed on hover, because a touchscreen has no hover. Collapsed to the icon
  rail, the Library draws only the folder the viewer stands in and the folders the tab
  strip holds open, with no shelf headings and no counts, because one glyph per folder is a
  wall rather than a list; it is rearranged only at its own width. The word for a group of
  folders is "shelf" in every dialog, menu, toast and confirm, and a shelf may be empty.
- **Footer.** The avatar menu ("Account") and nothing else, so the Library gets the room.
  Its items, in order: Settings, People, Trash, Import, Help, Sign out — the account's
  places, then the acts about the application, then the exit behind a separator.
- **Narrow widths.** Below 768px the sidebar is a drawer opened by "Menu" on a phone bar
  above the tab strip; the drawer closes on navigation, on its backdrop and on Escape. At
  that width the task surface of 9.3 takes the whole width in every mode and draws no
  resize handle.
- **Tab strip.** Session-scoped working state, never stored server-side. Every tab has one
  anatomy (mark, title, close), is closable and reorderable. The active tab is where the
  viewer stands; ordinary navigation retargets it, as an address bar does, and "Open in a
  new tab" appends one and goes to it. Navigating to a place a tab already holds activates
  that tab rather than opening or retargeting another. Closing the active tab lands on the
  neighbour; closing the last lands on Today, so the sole remaining tab draws no close
  control. A focused tab closes on Delete or Backspace and any tab on middle click; Ctrl+W
  stays the browser's. The "+" opens any shelf or folder as a tab, or begins New folder,
  New shelf, New task (a plain task, not a page's entry defaults) or Import. Tabs share one
  width between a floor and a ceiling, narrowing toward the floor as the strip fills and
  scrolling past it, so the last tab is never pushed out.
- **Window bar.** Belongs to the window, not the page: the active filter's removable chips
  at the left; the active tab's controls at the right (view strip, filter, the Activity
  line, the object's overflow). It never repeats the page title. A page adds a control
  there when the control belongs to the window rather than the body (Assignments' scope,
  9.5; a folder's member faces and Share, 9.6). A page fills it by portalling into it, so
  it keeps its own state while drawing into shell chrome (`app/src/client/components/window-bar.tsx`).
- **View strip** (`app/src/client/components/view-strip.tsx`). Offers only the views a page can honestly
  draw: list always; board wherever the page has a grouping (a column captures with its
  own value, and a drop writes that value); calendar only where having a date is what puts
  a task on the page, which is Scheduled. The chosen view is one client-side preference
  across pages; a page not offering it falls back to list without forgetting it. `?mode=`
  names a view. Every offered view is drawn at once, so a board or calendar is discoverable
  without hover; options not drawn stay in the group at no width and only the current
  option holds the tab stop. A disabled option names why in its tooltip.
- **Filter** (`app/src/client/views/FilterControl.tsx`). One control, one meaning on every place-page.
  Active state is removable chips, never a count alone. A filter belongs to the page and
  the session: kept on return, never carried to another page. Grouping replaces the
  page's own arrangement rather than nesting inside it.
- **Capture.** Every page has one always-visible capture point. Quick-add rows sit at a
  page's natural landing places; in board view every column captures and the floating
  button is absent; the floating "Add task" appears only on Today and Assignments. Every
  capture uses 9.3's entry defaults for where it stands, so a task made on a page appears
  on that page; in a hand-ordered list the new task lands at its foot, in typing order. A
  folder page captures through its canvas (9.6) instead.
- **Undo** (`app/src/client/components/undo-bar.tsx`, `app/src/client/shell/undo.ts`). One bar for the window, naming
  the act it takes back, for five seconds, Ctrl+Z / Cmd+Z; no redo. Each act registers its
  own inverse, and undo issues the inverse as a new mutation: no write is ever held back
  waiting for the window to close. The bar's wording is this section's and 4.13's event is
  written server-side in the mutation's transaction; neither is derived from the other.
- **The mark** (`app/src/client/components/dana-mark.tsx`). Inline SVG everywhere it appears. Its rest
  state is the whole logo, so a mark that never animates is simply the logo; each
  instance's mask id is unique; `prefers-reduced-motion` turns motion off, and a region
  may switch icon motion off wholesale.
- **Object acts** (`app/src/client/lib/object-acts.ts`). Every kind of thing declares its acts once and
  every overflow menu draws them through one component, so where a person stands never
  decides what they may do. Five groups in fixed order — reach, change, copy, stop,
  destroy — destroy last behind a separator; stopping (Abandon) and destroying (Delete)
  are never one group. An act with no handler is not drawn; a surface may add rendered
  items of its own above the contract's.
- **Panels.** A side panel takes room from the page rather than covering it; its width is
  one value the shell reads, shared by every panel, so two cannot overlap.
- **Library drag** (`app/src/client/shell/library-drag.ts`, `app/src/client/lib/use-sortable-list.ts`). Pointer-driven
  rather than HTML5 drag-and-drop, so it works on touch and auto-scrolls; the same list
  sorts by keyboard, the handle a real button.
- **Failure.** Offline, a global banner persists and writes fail with the offline toast;
  any other failed request shows the global error toast; a 409 shows 5.1's state-machine
  copy verbatim, and a stale page-block write (4.17) the same way. Words:
  `app/src/client/components/state-patterns.tsx`, `app/src/client/state/toasts.ts`.

Routes. Paths: `app/src/client/routes.ts`. /app redirects to /app/today, so a person with
nothing else asked for lands on Today (10.6 fixes the installed app's start_url at /app).
Desk is an ordinary folder page at its folder path, and /app/desk redirects there. The
retired paths /app/planned, /app/tasks, /app/all, /app/anytime, /app/important,
/app/done and /app/abandoned redirect, replacing the history entry, rather than 404,
because bookmarks exist; finished and abandoned work is reached through a folder's "Show
completed", not a page. A hidden (unpinned) page still renders at its URL.
/app/tasks/:id opens the task in the viewer's preferred surface over the page beneath; an
inaccessible or absent id answers with the 404 copy below, under 10.2.

An ellipsis in a label means one thing: a further step (a confirmation or a picker)
follows before anything happens. An act that takes effect on the press carries none.

Regions. Every section a page's structure names is a named region, named by its heading
or, where it has none, by the datum it is generated from: one per shelf in the sidebar;
Today's "Carried over", "Today", "Done today (N)"; one per Scheduled ladder rung; one per
person on Assignments, "Unassigned" last; one per user section on a folder page, plus "Done" and "Sharing panel"; one per board column, named by its value.
A collapsible section is a named region plus a control carrying that name, whose expanded
state is what open and collapsed mean.

Inline state copy (`app/src/client/components/ui/copy.ts`, `app/src/client/components/page/PageStates.tsx`):

| State | Copy |
| - | - |
| A read that failed, beside the thing that failed | "Couldn't load this. Nothing was changed.", with "Try again" |
| A resource that answers 404 (10.2) | "Not found. This may have been deleted, or it may never have been yours to see." |
| A response carrying truncated (section 6's cap rule) | "This list is long, so only the first part is shown. Narrow it down to see the rest." |
| A write refused by the storage quota (10.3) | "Out of space. Delete some files in Settings, or remove attachments you no longer need." |

The 404 sentence never distinguishes deleted from never-visible, which is 10.2's
non-disclosure rule said aloud. The inline failed-read line is the page's own words and
never the global toast's: a page saying "Nothing was saved" where nothing was being saved
tells a person something false about their own data.
