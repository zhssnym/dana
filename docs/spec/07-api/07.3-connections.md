### 7.3 Connections (roster)

- GET /connections. List of { user: {id, display_name, avatar_url, email}, connected_at },
  excluding soft-deleted users. Sorted display_name ascending, id. - DELETE
  /connections/:userId. Either side may call. Deletes the pair row; both rosters lose the
  entry; existing memberships untouched. 204; 404 if no such connection.

The roster element's email is not nullable, settled at the P5 shape review and entered by
owner ruling on 2026-08-10, and it is the one person shape in this contract that carries
an address at all. The exclusion this section's own bullet states, "excluding soft-deleted
users", is what makes the field total: 8.10's scrub is the only thing that empties 4.1's
column, and a scrubbed account is soft-deleted and therefore absent from this list.
Stating it in the shape rather than leaving it to the query is deliberate, because it is
what makes a lost deleted_at filter a failure rather than a null. 7.1 types the same
column nullable for the converse reason, that section carrying no equivalent exclusion;
the asymmetry is intended and neither reading generalizes to the other.
