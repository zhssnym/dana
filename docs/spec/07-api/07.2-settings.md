### 7.2 Settings

- GET /me/settings. { show_important, show_all, show_done }. - PATCH /me/settings. Any
  subset of the three booleans. Hidden pages are a navigation preference only; no data
  changes. 200.

Response body, escalated from the P2S opening session and entered by owner ruling: PATCH
/me/settings answers the GET /me/settings object, the same fresh-GET convention 7.1
carries on PATCH /me and 7.4 carries on each of its mutations.

**Annotation, 2026-09-04, issues #140 and #142: `calendar_zoom` joins the v2
settings bundle, which is a different endpoint from the two above and is
named in section 7 here for the first time.** Imran ruled on #140 that the
calendar's zoom follows the account rather than the browser, "consistent with
other durable preferences such as density, clock format, and task-open
surface", and left the storage and API shape to the owner, who ruled it onto
the existing bundle path rather than an endpoint of its own.

- `GET /api/v1/settings` and `PATCH /api/v1/settings` answer the v2 bundle of
  4.19: `{ theme, row_density, clock, task_open, calendar_zoom, pinned_views,
  sidebar_order, arrangements }`. PATCH takes any subset and answers the same
  object, the fresh-GET convention this section already carries for
  `/me/settings`.
- `calendar_zoom` is one of `day`, `week`, `month`, which are 9.5's three
  zooms; a fresh account reads `month`. A value outside the three is 422
  naming `calendar_zoom` and writes nothing, under the same rule 7.10 states
  for an enumerated parameter: absent and wrong are different states, and a
  wrong value is never quietly narrowed to the default. A stored value outside
  the three, which 4.10's CHECK makes unreachable, reads back as `month`.
- The two endpoints above are untouched. `/me/settings` is still exactly the
  three booleans and gains nothing here, which is what keeps AC-119 to AC-123
  as written.

**What this annotation does not do, said plainly rather than left to be
discovered.** The `/settings` pair has existed since RFC 0005 and section 7
has never enumerated it — not here, not in 7.10, not in an RFC — so before
today the only description of that endpoint anywhere was `app/src/shared/`
and 4.19's list of columns. This paragraph names it because a field cannot be
added to a contract that does not mention the endpoint carrying it; writing
the endpoint up properly, with its refusals and its relationship to frozen 7.2,
is separate work and a separate ruling. Section 7 is frozen and this is an
annotation on a human ruling, folded as text, in the shape 7.14's own
amendment uses. AC-378 to AC-380 assert the field.
