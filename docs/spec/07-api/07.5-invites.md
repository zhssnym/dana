### 7.5 Invites

Bodies and responses: `app/src/shared/invites.ts`.

- **POST /invites.** Body `postInvitesBody`. Validations V-INV (8.7): lowercase and
  syntax-check the email (422); reject V's own email (422); reject the default folder (409);
  reject a folder invite whose target is already a member (409 "already a member"); reject a
  task_id without a folder_id, or a task not in the folder (422). When a folder is attached
  and the email belongs to a roster connection of V, the invite converts to an instant share:
  200 `{ converted_to_share: true, membership }`, the membership being 7.4's members element.
  When no folder is attached and the email belongs to a roster connection of V, 409 "already
  connected" and nothing is created. Dedupe against INV-11: 409 naming the existing invite
  id. Rate limits in 10.4. Sends one email. 201 `postInvitesResponse`.
- **GET /invites/sent.** V's invites, newest first, any status (`getInvitesSentResponse`).
- **GET /invites/pending.** Invites addressed to V's email with status pending
  (`getInvitesPendingResponse`). Backs the login surface.
- **POST /invites/:id/accept.** Matched recipient only (404 otherwise, not 403, per the
  leak rule). Runs the acceptance transaction (8.7). 200 `acceptInviteResponse`, whose
  folder is the full Folder object, or null when no folder was granted: acceptance is the
  moment a client acquires a folder, so it gets everything a fresh GET would give. 409
  `folder_deleted` when the invite names a folder in Trash; the whole transaction rolls
  back, so the invite stays pending, no membership or connection is written, and restoring
  the folder makes the same invite acceptable again. The check holds even when the acceptor
  is already a member, since the response would otherwise hand them a folder they cannot
  open.
- **POST /invites/:id/decline.** Matched recipient only. 200 `{ invite }`.
- **POST /invites/:id/cancel.** Inviter or attached folder's owner. 200 `{ invite }`.
- **POST /invites/:id/resend.** Inviter only; 429 within 24 hours of last_sent_at. 200
  `{ invite }`.

All the transition endpoints answer 409 when the invite is not pending. Invariants: INV-9,
INV-11.

A bare invite to an existing connection is refused rather than parked because it can never
accomplish anything, where an invite into a full folder still parks because it becomes
acceptable the moment a member leaves. The three refusal codes on accept let a client tell
apart an invite that is not the caller's (404), one already settled (409 `conflict`), and
one still good against a folder that is not (409 `folder_deleted`).
