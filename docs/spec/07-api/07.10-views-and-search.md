### 7.10 Views and search

Queries and responses: `app/src/shared/views.ts`. All take tz (7.0). All return rows fully
ordered per section 6; ordering is server work, never client work.

- **GET /views/my-day** (`getMyDayResponse`), **GET /views/tasks** (`getTasksViewResponse`),
  **GET /views/planned** (`getPlannedResponse`), **GET /views/important**
  (`getImportantResponse`), **GET /views/all** (`getAllResponse`). Each carries `truncated`,
  the only way this contract reports section 6's row cap.
- **GET /views/planned/calendar?start&end&folder_id?** (`getPlannedCalendarResponse`).
  Without `folder_id`, the calendar spans every accessible Folder. With it, both real
  rows and repeating virtual instances belong to that exact Folder; an inaccessible or
  missing Folder answers 404. An invalid `folder_id` answers 422. The range answers 422
  when inverted or longer than 62 days. Bounded by its range alone: it carries no row
  cap and no `truncated`, and its virtual instances number up to one per day per series.
- **GET /views/done?cursor** (`getDoneResponse`).
- **GET /folders/:id/tasks?section=open|completed&cursor.** section defaults to open when
  absent, the state Q7 opens in. Open answers `getFolderTasksOpenResponse`; completed answers
  `getFolderTasksCompletedResponse`, paginated exactly like Done, because Q7's completed
  section is Q6 scoped to one folder.
- **GET /search?q&cursor** (`getSearchResponse`).

The folder inside a grouped view's groups is the TaskCard folder stub, not the Folder
object: a group heading needs exactly what a card's folder label needs, and the Folder's
counts and per-viewer fields are 7.4's business.

Cursors:

- A cursor is opaque: a client sends back the next_cursor it received, byte for byte, and
  reads nothing out of it. The encoding is not part of the contract, so no client depends on
  the sort keys of Q6 and Q8.
- A null next_cursor is the only end-of-list signal; an empty page is not one.
- A cursor an endpoint did not issue, or whose kind does not match the order being paged, is
  422 naming cursor, never a silent first page, which would hand the caller rows it has
  already seen with nothing on the wire to say so.
- A cursor's kind names the order it pages, not the endpoint that issued it, so a completed
  cursor is portable between GET /views/done and section=completed on the folder page.

A query parameter given a value outside what this section enumerates is 422 naming the
parameter, never narrowed to a default or the nearest legal value. A default answers absent
alone: a misspelled section=completed is refused rather than handed the open body.
