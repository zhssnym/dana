### 7.11 Server-authoritative versus client convenience

Server-authoritative, always revalidated regardless of client behavior: every permission
cell of 5.4; membership scope on every query; assignee membership and INV-5 forcing; the
date-dependency rules and clear-date cascade; status transitions, G-SERIES, and
generation; invite validations, matching, throttles, and rate limits; all input limits of
10.3; sort orders of section 6; today evaluation given tz; reminder computation and
delivery decisions.

Client conveniences with no authority, each shadowed by a server rule: disabling due_time,
reminder, recurrence inputs until a date exists; hiding the assignee field in
single-member folders; filtering the assignee dropdown to members; pre-filling defaults
per entry point; warning dialogs before destructive calls; disabling double submit. Any
rule found only in the client and not in this section's server list is a specification
violation.
