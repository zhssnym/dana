### 7.7 Steps

Bodies: `postTaskStepsBody` and `patchStepBody` in `app/src/shared/tasks.ts`.

- **POST /tasks/:id/steps.** position optional, defaulting to max plus 1. 422 over the 10.3
  step limit. 201 with the affected TaskDetail; the created step rides in its steps array
  with the id and position the server assigned.
- **PATCH /steps/:id.** Any subset of title, done, position. 200 with the affected
  TaskDetail.
- **DELETE /steps/:id.** 204, no body.
- **POST /tasks/:id/steps/:stepId/promote.** The step becomes a pending task titled after
  it, in the parent's folder and under the parent's section, created by V and assigned to
  nobody, and the step is removed in the same transaction. 201 with the new TaskDetail. 404
  when the step is not the named task's. A task never demotes: there is no reverse address.

All require membership of the parent task's folder (404 otherwise). Steps never affect task
status. A step mutation answers the parent TaskDetail because a step has no object or GET of
its own, and the call also moves steps_done and steps_total.
