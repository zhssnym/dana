### 7.4 Folders and membership

- GET /folders. All accessible folders as Folder objects. Sort: is_default first, then
  lower(name), id. - POST /folders. { name }. Creates folder with owner = V plus owner
  membership (one transaction). 201 Folder. 422 name length; 422 when V already has 200
  custom folders (limit, section 10.3). - GET /folders/:id. Folder plus members [{user,
  role, joined_at, is_owner}] plus pending invites [{id, email, task_id, created_at,
  last_sent_at}]. 404 if not member. - PATCH /folders/:id. { name }. Owner only (403
  otherwise); works for the default folder too (rename allowed). 200. - DELETE
  /folders/:id. Owner only. 409 if is_default (INV-2). Executes the deletion cascade
  (section 8.8). Response 200 { deleted: {tasks_open, tasks_completed, tasks_abandoned} }
  so the client can confirm what the dialog promised. Invariants: INV-1 via cascade. -
  PATCH /folders/:id/my-membership. { label, color }, either nullable. Any member, own row
  only. 200. - POST /folders/:id/members. { user_id }. Any member; guards per 5.3 row 1:
  409 default folder, 409 already member, 422 no roster connection between V and target,
  422 member cap 25. Sends share-grant email. 201. - DELETE /folders/:id/members/:userId.
  Three legal shapes per 5.3: owner removes another member; non-owner removes self
  (leave); owner removes self, which transfers ownership first when other members exist
  and is 409 "delete the folder instead" when sole member. All run R-CLEAN. 204.
  Invariants: INV-4, INV-5, INV-10.

Response shapes, settled at the P2 shape review and entered by owner ruling: GET /folders
answers the bare array of Folder objects, no wrapper key. The folder detail's invite key
is pending_invites, its elements carrying exactly the five fields above. The user object
inside a members element is {id, display_name, avatar_url}, the person shape TaskCard's
assignee carries, and includes no email. A 7.4 mutation answers what a fresh GET would:
PATCH /folders/:id and PATCH /folders/:id/my-membership answer the Folder object, and POST
/folders/:id/members answers the members element it created.

The Folder object carries `cover_preset` (text or null) and `cover_focal_y` (0 to 100)
beside `cover_file_id`. PATCH /folders/:id takes `cover_preset` (nullable) and
`cover_focal_y` beside `cover_file_id`, any member as for the rest of the 4.3 identity; a
body naming both a file and a preset is 422, and setting either source clears the other.
