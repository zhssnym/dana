### 7.29 Consultation input rounds

"Ask for input" inside a Discussion (issue #321). The data model is 4.33. Wire shapes:
`inputRoundSchema` and the request bodies in `app/src/shared/consultation-input.ts`.

## The refusal order

**404 → 422 → 403 → 409**, as 7.28. A person who is not a member of the Discussion's Folder
(or whose Folder is in Trash) is 404 on every route. The mode-specific body checks are 422, the
preset is 403, and state is 409: a resolved or trashed Discussion, a closed round, a second open
round. Every mutation decides under the Discussion's row lock, with access resolved in the
same transaction, so a downgrade takes effect on the next request.

## Who may do what

| Act | Who |
| - | - |
| Read rounds, responses, counts | Can view+ (`discussion.read`) |
| Open a round | Can edit+, or the Discussion's creator while they hold Can comment (`input_round.open`) |
| Close a round | Can edit+, or the Discussion's creator while they hold Can comment (`input_round.close`) |
| Submit, change, withdraw one's own response | Can comment+ (`input_round.respond`) |

Authorship alone confers nothing: a creator lowered below Can comment loses both creator
powers at once.

## The InputRound object

`id`, `discussion_id`, `mode`, `prompt`, `state`, `created_by`, `created_at`, `close_reason`,
`closed_by`, `closed_at`; `options` (position order, empty unless `choose`); `responses` (every
current response with its `user_id`, oldest first: M1 has no anonymous input); `choice_counts`
(`choose` only: one `{option_id, count}` per option, zeros included, and nothing that names a
winner; null for `advice` and `concerns`); `my_response` (the caller's own, or null).

## The routes

**GET /discussions/:id/input-rounds**: `{ input_rounds }`, newest first. At most one is open.

**POST /discussions/:id/input-rounds**: 201 with the round. Body `{ mode, prompt, options? }`.
`prompt` is 1 to 1000 characters. `choose` requires 2 to 20 distinct `options` of 1 to 200
characters each; any other mode refuses `options` (422). 409 when the Discussion is resolved or
in Trash or already has an open round.

**GET /input-rounds/:id**: the round.

**POST /input-rounds/:id/close**: 200 with the round, now `closed` with `close_reason: closed`.
409 when already closed or the Discussion is in Trash.

**PUT /input-rounds/:id/response**: 200 with the round. Submit or change the caller's own
response. `choose` takes `option_id` (an option of this round) and nothing else; `advice` takes a
non-blank `body` and nothing else; `concerns` takes `concern` (`no_concern | concern`), and `body`
is the reason, required for `concern`. 409 when the round is closed or the Discussion is
resolved or in Trash.

**DELETE /input-rounds/:id/response**: 204. Withdraws the caller's own response; withdrawing
none is the same 204. 409 in the same states as PUT.

## Resolve and reopen

Resolving a Discussion closes its open round in the resolve's own transaction
(`onDiscussionResolved` in `app/src/server/domain/consultation-hooks.ts`), with
`close_reason: discussion_resolved`. Reopening a Discussion reopens no round; a new one may
be opened.
