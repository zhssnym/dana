### 4.16 files

One row per stored object: an image on a page, a comment's attachment or
voice note, a cover upload, an avatar, a composer file, audio or video asset.
Bytes live in the object store (section 11); this table is the authority on
existence, ownership and quota.

Columns and constraints: `app/db/migrations/0003_v2_expand.sql`, widened by
`0009_file_dimensions.sql`, `0012_covers_for_every_page_kind.sql`,
`0014_files_unreferenced_since.sql`, `0015_folderless_page_images.sql` and
`0024_files_and_media_blocks.sql`. The kind vocabulary, the folder-less kinds
and the MIME allowlists live once, in `app/src/shared/files.ts`, because the
browser needs them as much as the server does.

What the columns mean:

- `id` is also the object-store key. `owner_id` is whose quota the row spends;
  the quota (1 GB per user, `QUOTA_BYTES` in `app/src/server/domain/files.ts`,
  10.3) sums `bytes` by owner with no regard to folder.
- `folder_id` is the visibility scope. **`voice` is the only kind that requires
  a folder**: a voice note hangs on a comment thread, which always lives in a
  folder. Every other kind may be folder-less because its scope matches its
  page's or its person's: an avatar belongs to a person, and a cover or composer
  asset takes its page's scope, and a shelf page (4.18) has no folder. The caller
  chooses by sending a `folder_id` or not.
- `width` and `height` are the pixels of the **stored** object, after 7.15's
  rotate and downscale, read off the re-encode that already happens. They belong
  to the file and not to the block, because one image can be placed on several
  pages and its shape is a fact about the bytes; no write shape carries them.
  **Null means unknown**, and a consumer draws exactly what it would with no
  dimensions. Rows stored before the columns existed were never backfilled.
- `duration_ms` is written for `voice` only. `audio` and `video` store no
  duration: reading one would need media probing, and the browser discovers it
  at playback.
- `unreferenced_since` is when the last reference to the row went, written and
  cleared by the 11.7 tick; null means referenced or not yet looked at. It
  exists because nothing else records when a reference was dropped, and 7.19's
  reclaim ages from it, never from `created_at`, which would reclaim a cover worn
  until this morning. **It is not a reference count and must not become one**:
  "referenced" stays a query over the foreign keys that name `files(id)`.

**Serving** passes 10.2 like every read; there are no public object URLs. A
folder-scoped file is its members'; an **avatar** is readable by any signed-in
account, because a member list renders other people's pictures; **every other
folder-less file is its owner's alone**, whatever its kind. The last clause
must stay kind-blind: a predicate that enumerated folder-less kinds fails open
the day a kind is added. A folder page's block may name only a file of that
folder (7.16); a folder-less image or asset can be named only from a shelf page.

**`voice` is not `audio`, and nothing converts between them.** A `voice` row is
a comment's recorded note, capped by 10.3's ten-minute rule and accepting
`audio/*` at large; an `audio` row is a track uploaded into a page. A shared
kind would have to hold both to one duration cap.

**A file's kind is declared by the caller, validated by the server, then
preserved.** No later path re-derives it from the name, extension or stored
MIME: the same JPG is an `image` when dropped as media and a `file` when
inserted through the File command, and that is a decision a person made.
Filename and extension are presentation, never security truth.

**`audio` and `video` accept a short allowlist of containers a current browser
plays unaided**, checked against the declared type plus a container-signature
read of the leading bytes; this is container validation, not codec validation.
QuickTime is absent because `.mov` plays in some browsers and not others.
Refusing to preview is cheap, claiming playback that does not work is not, and
anything off the list still uploads as a generic `file` offered for download.

**Inline serving is an allowlist, never a denylist**, so a kind added later is
served as an attachment by default on this origin. The kinds that pass a
validation on the way in (the raster kinds through sharp's re-encode, `audio`
and `video` through the allowlist, `voice` through its own rule) are served
inline; `file` is served `Content-Disposition: attachment` with `nosniff`,
always. **SVG stays out of the raster set**: it decodes like an image and serves
like a document, and a document with scripts on this origin is a session lost.

**Reclaim** (7.19): a folder-less row of any kind but avatar
(`RECLAIMABLE_KINDS` in `app/src/server/domain/files.ts`) that nothing
references is destroyed thirty days after its `unreferenced_since` mark, since
once its block or page is gone no surface lists it and it would spend its
owner's quota for ever. A folder-scoped file is untouched, being listed in its
folder and deletable by its members.
