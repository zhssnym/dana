### 4.9 invites

| Column | Type | Null | Default | Constraint |
| - | - | - | - | - |
| id | uuid | no | generated | PK |
| inviter_id | uuid | no | none | FK users(id) |
| email | text | no | none | CHECK (email = lower(email)); length up to 320 |
| folder_id | uuid | yes | none | FK folders(id) ON DELETE CASCADE (folder deletion removes pending grants) |
| task_id | uuid | yes | none | FK tasks(id) ON DELETE SET NULL; CHECK (task_id IS NULL OR folder_id IS NOT NULL) |
| status | text | no | 'pending' | CHECK (status IN ('pending','accepted','declined','canceled','invalidated')) |
| last_sent_at | timestamptz | no | now() | resend throttle anchor |
| responded_at | timestamptz | yes | none | set on any terminal transition |
| accepted_by | uuid | yes | none | FK users(id); the account that accepted |
| responsibility | jsonb | yes | none | CHECK (`responsibility IS NULL OR folder_id IS NOT NULL`) as `invites_responsibility_requires_folder_check`; the initial Responsibility document the invitation carries. **Added 2026-09-21 by issue #230** |
| created_at | timestamptz | no | now() | none |

Partial unique index enforcing INV-11: UNIQUE ON (inviter_id, email, COALESCE(folder_id,
'00000000-0000-0000-0000-000000000000')) WHERE status = 'pending'. Index on (email) WHERE
status = 'pending' for the at-login lookup (Q12); index on (inviter_id) for the sent list.
Rationale: task_id records assignment intent applied at acceptance (section 8.7); a
deleted folder cascades its pending invites away, which is the required invalidation
expressed as removal; the invalidated status is used when the inviter's account is
deleted.

**Annotation, 2026-09-21, issue #230, on the accepted technical ruling**
https://github.com/zhssnym/dana/issues/230#issuecomment-5751322947 **(Ruling 1, section
4).** One nullable column is appended and nothing else on this table moves.

**It is parked content rather than a document.** An invitation names an email address, and
there may be no account behind it yet, so there is nobody to hold a 4.28 row for. The
content therefore waits here and becomes a document with its first revision **at
acceptance**, whose actor is the inviter who chose the text rather than the person who
accepted it — AC-569 drives both halves. An invitation that never becomes a membership
never becomes a document either, and the column goes with the row.

**The CHECK is what makes "Responsibility without a folder" unrepresentable.** A
Responsibility is a fact about a membership of a folder, so an invitation naming no folder
carrying one would be a statement about nothing; the route answers 422 and the constraint
means a path that forgot to cannot write one anyway.
