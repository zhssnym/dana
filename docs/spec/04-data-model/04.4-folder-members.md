### 4.4 folder_members

| Column | Type | Null | Default | Constraint |
| - | - | - | - | - |
| folder_id | uuid | no | none | FK folders(id) ON DELETE CASCADE |
| user_id | uuid | no | none | FK users(id) ON DELETE CASCADE |
| role | text | no | 'member' | CHECK (role IN ('member')); reserved for v2 tiers |
| label | text | yes | none | length 1 to 40 (`folder_members_label_length_check`); the viewer's own Shelf membership. **Superseded by `shelf_name`; dropped by issue #247** |
| shelf_name | text | yes | none | length 1 to 40 (`folder_members_shelf_name_length_check`); the same fact under the name 4.18 uses. **Added 2026-09-20 by issue #226** |
| color | text | yes | none | CHECK matches '#RRGGBB' hex pattern |
| created_at | timestamptz | no | now() | join instant; drives ownership transfer order (section 8.9) |

PK (folder_id, user_id) (INV-10). Index on (user_id): the accessible-folders lookup joined
by every page query (Q9). Rationale for the shelf membership and color living here rather than on
folders: they are per-member personal grouping; Imran's shelf never changes what Hassan
sees.

**Annotation, 2026-09-20, issue #226, on the technical ruling recorded there.** `label` has
never meant classification: it is the viewer's own Shelf membership, held in step with
`shelves.name` by 4.18, and the word was needed back by #208's Label model (4.24), where it
means something else entirely. The column is therefore **added beside rather than renamed**,
which is the whole of the amendment to this table.

**It is expand-and-contract because a rename would be an outage, and the argument is worth
keeping because the first draft got it wrong.** The case for one `ALTER ... RENAME COLUMN`
was that migrations run at boot before the process serves and that Dana runs exactly one
production instance. The first half is true. The second is true of *steady state* and not of
a deploy: 11.11 has Render bring the new instance up and pass its health checks before
draining the old one, so between the statement committing and traffic switching there is a
window in which the old instance is still serving and every one of its folder reads selects
a column that no longer exists. That is `GET /folders`, the sidebar and every folder page —
a total outage of the main surface for the length of a deploy. Hard stop 1 is written for
exactly that.

So migration 0022 adds `shelf_name` with its own named CHECK and backfills it, leaves
`label` and `folder_members_label_length_check` untouched, and **for this release the
application reads `shelf_name` and writes both.** An old instance reading `label` through
the deploy window therefore sees current data rather than a missing column.
`db/constraint-catalog.ts` carries both columns and both CHECKs for the same release, and
AC-479 asserts that the two **agree** rather than that the old one is gone. **The contract
half is issue #247**, which drops `label`, its CHECK and the second write together, and must
not merge until 0022 is live in production. The wire carries the same pair for the same
release and the same reason; 7.4 and 7.0 carry that half.

Nothing about Shelf semantics moved with the name: the 1-to-40 bound, and all three
directions in which 4.18 holds membership and shelf name in step, are what they were.
