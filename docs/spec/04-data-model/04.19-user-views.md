### 4.19 user_views

A saved view: a filter state given a name and a pin (DES-153's second half).
Serialized by ids, never display names.

Columns and constraints: `app/db/migrations/0003_v2_expand.sql`. `definition`
is the filter model, zod-validated at write and holding ids only; its wire
shape is `postViewBody` in `app/src/shared/bundle.ts`.

The per-user view and display preferences (row density, clock, theme,
task-open surface, pinned native views, sidebar order, arrangement keys) are
columns of `user_settings` (4.10), served as the settings bundle (7.23).
Pinned native views are derived at read time rather than stored twice, so two
records of one fact are never kept.

**The task-open surface defaults to `panel`**, Side peek (migration
`0036_task_started_at.sql`, which reverses 0010's `dialog` and moves every
stored `dialog` to `panel`, leaving `tab` alone: the build before it always
opened the side panel whatever the row said, so `panel` is what every account
was already seeing). The column is the record for all three values, read as
"Open tasks in": `panel` Side peek, `dialog` Center peek, `tab` Full page; the browser keeps a mirror only so the
first render can read it synchronously, refreshed when the bundle arrives and
cleared at sign-out.
