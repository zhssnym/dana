### 4.14 notifications

The fan-out of an event to the people it concerns: each newly added assignee of an assignment, the
participants of a thread, the members of a deleted shared folder. Derived rows; deleting
an event does not retract its notifications.

Columns and constraints: `app/db/migrations/0003_v2_expand.sql`.

`user_id` is the recipient; a null `read_at` is unread. UNIQUE (user_id, event_id) makes
fan-out idempotent, so a tick replayed after a crash lands on the constraint (11.7). An
actor is never notified of their own act.

**`mention_notices`** (migration `0041_mentions.sql`) is the ledger behind the `mentioned`
event. A person mention is a rich-text run `{ text, mention: { user_id } }` in a block or a
post; one row per (source, person) records that the person was told, inserted
`ON CONFLICT DO NOTHING`, so re-saving writing that still names someone never tells them
twice. Only members of the page are told (a non-member gets no row); a
Shelf tell nobody. A save that tells anyone records one `mentioned` event, fanned to the
people newly told. `user_id` cascades, which never fires (8.10 scrubs rather than
deletes), so account deletion sweeps the rows itself.
