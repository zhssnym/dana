### 4.29 folder_responsibility_history

**Added 2026-09-21 by issue #230, on the accepted technical ruling**
https://github.com/zhssnym/dana/issues/230#issuecomment-5751322947 **(Ruling 1, section 4).**
Product authority: #209 R10 and the accepted R10B.

The append-only record behind 4.28: every committed revision of a Responsibility document,
every ending of a standing, and both directions of the self-edit grant. Nothing in this
table is ever updated or deleted by the application.

| Column | Type | Null | Default | Constraint |
| - | - | - | - | - |
| id | uuid | no | generated | PK `folder_responsibility_history_pkey` |
| folder_id | uuid | no | none | FK folders(id) ON DELETE CASCADE (`folder_responsibility_history_folder_id_fkey`) |
| member_id | uuid | no | none | the subject. FK users(id) ON DELETE RESTRICT (`folder_responsibility_history_member_id_fkey`) |
| responsibility_id | uuid | yes | none | FK folder_responsibilities(id) ON DELETE CASCADE (`folder_responsibility_history_responsibility_id_fkey`) |
| transition | text | no | none | CHECK in (`responsibility_created`, `responsibility_updated`, `responsibility_ended`, `self_edit_granted`, `self_edit_revoked`) as `folder_responsibility_history_transition_check` |
| revision_no | integer | yes | none | see `folder_responsibility_history_revision_check` |
| content | jsonb | yes | none | the snapshot as committed; never rewritten |
| content_hash | text | yes | none | the snapshot's canonical hash |
| actor_id | uuid | no | none | who did it. FK users(id) ON DELETE RESTRICT (`folder_responsibility_history_actor_id_fkey`) |
| effective_at | timestamptz | no | now() | none |

CHECK `folder_responsibility_history_revision_check`:

```
(revision_no IS NULL) = (content IS NULL)
AND (content IS NULL) = (content_hash IS NULL)
AND (content IS NOT NULL) = (transition IN ('responsibility_created', 'responsibility_updated'))
AND (revision_no IS NULL OR revision_no > 0)
```

CHECK `folder_responsibility_history_document_check`: `responsibility_id IS NOT NULL OR
transition IN ('self_edit_granted', 'self_edit_revoked')`.

Unique index `folder_responsibility_history_revision_no_idx` on (`responsibility_id`,
`revision_no`) WHERE `revision_no IS NOT NULL`. Indexes
`folder_responsibility_history_folder_id_effective_at_idx` on (`folder_id`,
`effective_at`) and `folder_responsibility_history_member_id_effective_at_idx` on
(`member_id`, `effective_at`).

**The revision CHECK is the shape rule written where it cannot be forgotten.** An entry
that carries content carries a revision number and a hash and is a creation or an update; an
entry that carries none of the three is an ending or a grant toggle. Written as three
biconditionals rather than as `NOT NULL` columns because the same table holds both shapes,
and written over columns that are never UNKNOWN because a CHECK passes on UNKNOWN — 4.24
records the same hazard for its own ownership check, and it is the reason both are spelled
this way.

**The partial unique index is what makes a revision immutable in the database rather than
in prose.** Two entries cannot hold one revision number of one document, so a "correction"
has to arrive as the next revision and the earlier text stays exactly as its author left
it. AC-565 and AC-568 drive it, and there is deliberately no route in section 7 that
updates or deletes a row of this table.

**The grant toggles live here rather than in 4.13's events, because they are about this
document.** A grant is the permission to write one Responsibility; recorded beside the
revisions it makes possible, "who let them" and "what they then wrote" read as one story
from one table ordered by `effective_at`.
