### 4.7 my_day_entries

| Column | Type | Null | Default | Constraint |
| - | - | - | - | - |
| task_id | uuid | no | none | FK tasks(id) ON DELETE CASCADE |
| user_id | uuid | no | none | FK users(id) ON DELETE CASCADE |
| added_on | date | no | none | the adder's local date at pull time |

**Annotation, S29 fold, 2026-08-27. This table keeps its name and its rows are called
Today entries.** RFC 0005 renamed the page from My Day to Today and deliberately did not
rename the table, section 2 stating the rule that a stored identifier is not display copy.
So `my_day_entries` is correct wherever it appears in sections 4, 6 and 7, and "My Day
entry" is not: the glossary's term is **Today entry**. Section 4 is frozen and this is an
annotation rather than an edit.

PK (task_id, user_id) (INV-12). Index on (user_id) for Q1. Rows are additionally deleted
by the member-removal and leave transactions for tasks the user loses access to; the
task-deletion cascade covers the rest.
