### 4.31 discussions

One row is one **Discussion** in one Folder's Consultation (issue #320, product
authority #212 R1, R2, R4). Columns, constraints and indexes:
`app/db/migrations/0029_consultation_discussions.sql`.

- `state` is exactly `open | resolved`; there are no Discussion types.
- `discussions_resolution_check` makes `resolved` equivalent to both
  `resolved_at` and `current_outcome_id` being set, so a resolved Discussion
  always has a current Outcome and an open one never does. Resolve inserts the
  Outcome and flips the row in one transaction; reopen clears
  `current_outcome_id`, `resolved_at` and `resolved_by` and deletes nothing.
- `discussions_current_outcome_fkey` holds `(id, current_outcome_id)` against
  `discussion_outcomes (discussion_id, id)`, so the current Outcome is always
  one of the Discussion's own. It is NO ACTION because the two tables
  reference each other and a Folder purge cascades to both in one statement.
- `context` is plain text, at most 4000 characters, NULL when absent.
- `created_by` and `resolved_by` are provenance, never authority (#228); both
  keys on `users` are RESTRICT and outlive the account (8.10).
- `trashed_at` is Trash: non-destructive and restorable. Permanent purge is a
  DELETE, which cascades to the Discussion's Outcomes and comments.
- `last_activity_at` orders the Consultation list
  (`discussions_folder_activity_idx`, partial on `trashed_at IS NULL`).
- `discussions_folder_id_id_key` exists so `comments` can hold a composite key
  to `(folder_id, id)`: a comment's Discussion is in the comment's own Folder.

**Migration 0029's backfill.** Each Folder with Folder-level comments
(`task_id IS NULL`), trashed and default Desk Folders included, received exactly
one open Discussion titled "General discussion", `created_by` the Folder owner,
`created_at` its earliest comment's time and `last_activity_at` its latest, and
every such comment was pointed at it. Folders without Folder-level comments
received none.
