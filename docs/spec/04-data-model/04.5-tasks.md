### 4.5 tasks

Columns and constraints: `app/db/migrations/0000_core_schema.sql`, `0003_v2_expand.sql`
(`section_block_id`, `deleted_at`, the `(folder_id, id)` unique), `0005_ruled_schema.sql`
(`position`), `0016_compose_first_canvas.sql` (`page_position`) and
`0018_task_start_date.sql` (`start_date`).

- **Dates are floating** (4.11). `start_date` is when the task is intended to begin, and
  never falls after `due_date`; nothing infers one. `due_time` requires a date; v2
  interfaces do not set it, and existing values are honored. `recurrence_rule` requires a
  date and a `series_id` (INV-13).
- **`project_id` is the task's folder's project** (step 8, 0062), set by a trigger and held
  by `tasks_folder_project_fkey (folder_id, project_id)`, whose ON UPDATE CASCADE carries it
  when a page moves to another project.
- **Every assignee must be a member of the task's project (INV-4)**. `assignee_ids` is the
  ordered, unique list. `assignee_id` remains its first element for older clients and as
  the timezone anchor of the task's one reminder. Migration 0063 backfills existing
  assignments and validates list writes with a trigger. The first element is also enforced by the
  composite FK `(project_id, assignee_id)` to `folder_members`
  (`tasks_assignee_project_member_fkey`), which sets only `assignee_id` null when the
  membership goes. A page moves only into a project with the same people (7.4), so a move
  never strands an assignee. The column-targeted SET NULL needs Postgres
  15 or later; section 8.8 also unassigns inside the member-removal transaction, so the FK
  is belt and braces. It also validates folder moves: changing `folder_id` with a stale
  assignee fails at the database.
- **`completed_at` and `completed_by` are set exactly when status is completed.**
  `completed_by` feeds the My Day recap (Q1R), makes the completion race guard natural
  (8.5), and feeds the activity log of 4.13.
- **`series_id` groups a recurrence chain** for guards (INV-7) and Done-page trails.
- **`updated_at` is touched on every mutation**: the last-write-wins tiebreak evidence
  and the search recency key.
- **`section_block_id`** is the section this task sits under on its folder's page (4.17);
  null is the loose block.
- **`position`** is the hand order of a folder's unscheduled list, null until that folder
  is first arranged by hand. **`page_position`** is the task's place in 4.17's mixed
  folder-page sequence, nullable so an older instance can still insert during a rolling
  deploy. Both are fractional keys under `COLLATE "C"`, allow gaps and ties, and order by
  (key, id).
- **`deleted_at` marks Trash**, purged by the 11.7 pass at 30 days. Reads exclude trashed
  rows except through 7.13, the same guard 4.3 states for folders; a task in a trashed
  folder is unreachable while its folder is, and purges with it.
