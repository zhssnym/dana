### 4.20 user_page_covers

One person's cover on one of Dana's place pages. Columns and constraints:
`app/db/migrations/0005_ruled_schema.sql`.

- **A cover is either a stored file or a built-in preset, never both and never
  neither**, so a row exists exactly when a cover was chosen and removal is the
  row's deletion. The file foreign key cascades for the same reason: deleting
  the picture deletes the cover.
- `focal_y` is the vertical reposition as a percentage.
- The `place` set is 4.19's native-view vocabulary minus `desk`, which is a
  folder and carries 4.3's own cover column. A place's cover key and its pin key
  are one string.
- `preset` is checked for shape, not against a list of names: the built-in
  covers are the design system's vocabulary and must be able to change without
  a migration.
- **A table rather than columns on `user_settings`**: a folder's cover is shared
  by its members, but a place page is Dana's own furniture and each person's
  cover on it is theirs — a per-viewer fact keyed by person and place, which
  would otherwise make every new place a migration of the settings row.
- No index: the primary key serves the only read, one viewer's covers.
