### 4.20 user_page_covers

| Column | Type | Null | Default | Constraint |
| - | - | - | - | - |
| user_id | uuid | no | none | FK users(id) ON DELETE CASCADE |
| place | text | no | none | CHECK (place IN ('today','scheduled','assignments','important','all','done','abandoned','anytime')) |
| file_id | uuid | yes | none | FK files(id) ON DELETE CASCADE |
| preset | text | yes | none | CHECK matches '^[a-z0-9-]{1,40}$'; a built-in cover named by the design system |
| focal_y | integer | no | 50 | CHECK (focal_y BETWEEN 0 AND 100); the vertical reposition, as a percentage |
| updated_at | timestamptz | no | now() | none |

PK (user_id, place). CHECK ((file_id IS NULL) <> (preset IS NULL)): a cover
is either a stored file or a built-in, never both and never neither, so a
row exists exactly when a cover was chosen and removal is the row's
deletion. The place set is 4.19's native-view vocabulary minus `desk`, which
is a folder and carries 4.3's own cover column. No index: the primary key
serves the only read this table has, which is one viewer's covers.

**Rationale, 2026-09-21, folded from RFC 0005 under the technical ruling of that date**
(https://github.com/zhssnym/dana/issues/280#issuecomment-5754491849, issue #280). It
changes no column, no constraint and no rule above; only the reasoning moves.

*Why a table rather than columns beside the person's settings.* A folder's cover is the
folder's, and every member sees the same one; a place page is Dana's own furniture, and
each person's cover on it is theirs. A per-viewer fact keyed by the person and the place is
a row, and the alternative — one group of columns per place on `user_settings` — makes
every new place a migration of the settings row and stores nothing the primary key above
does not.

*Why the `place` CHECK holds eight and the ruling named six.* The ruling that asked for
place covers named six places. Assignments and Abandoned are place pages by the same
definition it used, so the table was written to carry eight, and the key vocabulary is
4.19's own rather than a second spelling of it — a place's cover key and its pin key are
one string. That is a widening of a ruling rather than a reading of it, and it is recorded
here because nothing else in the tree now records that the ruling said six.

*Why the preset is checked for shape and not against a list of names.* The built-in covers
are the design system's vocabulary. A CHECK naming them would put that vocabulary inside a
frozen section, where a swatch added, renamed or dropped by a later design round could not
reach it without a ruling on section 4. The format check holds the shape of a key and
leaves the names where they can still change.
