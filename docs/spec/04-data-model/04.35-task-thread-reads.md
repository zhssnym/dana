### 4.35 task_thread_reads

One row is **when one person last opened one Task's thread** (its comments, 4.15, with
`task_id` set). Columns, constraints and indexes:
`app/db/migrations/0049_task_thread_reads.sql`.

The row is written only by 7.28's `PUT /tasks/:id/thread/read`, which upserts `read_at` to
now; no row means the person has never opened the thread. It is 4.34's twin for Task
threads, kept on the server for the same reasons: unread state follows a person between
devices, and opening a thread clears the bell for it. It is one person's own state: nobody
else reads it, and no event records it.

The Task key cascades, since a marker on a purged Task means nothing. The `users` key
cascades too but never fires, because 8.10 scrubs the `users` row rather than deleting it;
account deletion removes these rows itself.
