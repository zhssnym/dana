### 4.10 user_settings

Columns and constraints: `app/db/migrations/0000_core_schema.sql`, `0003_v2_expand.sql`
(the v2 preferences 4.19 lists), `0004_pinned_views.sql`, `0010_task_open_default_dialog.sql`,
`0013_calendar_zoom.sql`, `0036_task_open_side_peek.sql` (`task_open`'s default back to
`panel`) and `0050_focus_lists.sql`. The API over them is the settings bundle of 7.23.

- **`show_important`, `show_all` and `show_done` are v1's page-visibility flags and are
  read-only.** Which places appear in the sidebar is `pinned_views` (9.7). While
  `pinned_views` is null (never chosen) the pins derive from the three flags; once the
  person writes pins, `pinned_views` is the record. The derivation exists so that two
  records of one fact are never both authoritative for one reader. Nothing writes the
  flags; dropping them is a later contract migration once nothing reads them.
- **`calendar_zoom` is a durable account preference**, not browser state, so it follows
  the account across devices like density, clock format and task-open surface, and never
  becomes a second, browser-only record. Its values are the calendar's own zoom keys
  (9.5); year zoom is not offered. The default, `month`, is what a fresh account has
  always seen.
- **`focus_lists`** is an ordered array of list keys (`today`, `scheduled`, `assignments`,
  `important`, `overdue`, `undated`, `open`), defaulting to the first three, still validated
  and stored (7.23). The sidebar no longer reads it: its Focus lists are fixed (9.1), and a
  stored key for a removed list causes no error and is never rewritten.

Session storage is stack-dependent and out of the core model; its requirements live in
section 10.1.
