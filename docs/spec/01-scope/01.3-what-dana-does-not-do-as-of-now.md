### 1.3 What Dana does not do as of now

| Item | Reason | Earliest return |
| - | - | - |
| Dana AI chat | Deferred by design; needs model infrastructure | Deferred, no date |
| Sharing content with Dana (extraction) | Reuses the chat engine; must follow it | Deferred, no date |
| Automatic email inbox scanning | Sensitive Gmail OAuth scope, security assessment and annual re-verification burden on a two-person team | Deferred, no date |
| Calendar linking | Unsolved design problem: free-slot inference is wrong too often | Unscheduled |
| Stats page | Value unclear; the folders and durations it would need are themselves reduced | Deferred, no date |
| Templates as an object of their own | Far future. A folder or shelf is already saved and imported as a workflow file (7.16), which is the structural half; what is absent is a named, reusable template with a life of its own | Unscheduled |
| Realtime sync, presence | Last-write-wins with refetch is sufficient at current scale | Deferred, no date |
| Offline writes and sync engine | Largest hidden subsystem in the category | Deferred, no date |
| SMS reminders | Vendor, cost, sender registration | Unplanned |
| Web push reminders | Per-device subscriptions; iOS constraints need verification | Deferred, no date |

**Three rows left this table at the S29 fold of 2026-08-27 because Dana now does the
thing**, and each is named here rather than deleted silently, since a reader who knew the
old table will look for them. **Attachments** are sections 4.16, 7.15 and 10.3, and the
quota is what answers the storage and scanning cost that row gave as its reason.
**Activity log** is 4.13 and 7.12, and the `completed_by` column that row said was
preparing for it is now one of its inputs. **Drag reordering of tasks and folders** is
`tasks.position` plus the shelf and sidebar arrangements of 4.18 and 4.19; the
"personal-versus-shared ordering unanswered" that row gave as its reason was answered by
RFC 0005 change control item 44, a hand order being the folder's and a shelf arrangement
being the member's.

**Dana AI chat stayed and its date did not.** That row read "earliest return v2", and v2
is the release this table now describes; the cell was a promise the product had already
broken. It is called out separately from the three above because the shape of the mistake
is the opposite one, and both shapes are what this table has to be audited for whenever a
release lands.

**Every "v1" and "v1.1" in the last column is now a date rather than a version number, and
where re-dating a row would have been a product decision it reads "Deferred, no date".**
Those cells were written when v1 was the next release and v1.1 was a real slot on
somebody's plan. Neither is true now, and a specification carrying a stale schedule
teaches a reader to trust a date nobody set. Re-dating them is the owner's, and one
sentence from him closes as many rows as he likes.
