### 4.18 shelves

A person's shelf: the per-user container whose *membership* is
`folder_members.shelf_name` (4.4) and whose page needs a stable key that a
rename cannot move. The id never changes.

Columns and constraints: `app/db/migrations/0003_v2_expand.sql`, with the cover
columns and their CHECKs in `0012_covers_for_every_page_kind.sql`.

Shelves are private by construction (DES-195/196): no member rows, no share.

**Membership and shelf name are held in step in all three directions, in one
transaction:** a rename rewrites the viewer's matching `shelf_name` values, a
delete clears them, and a `shelf_name` written through 7.4 names a shelf, made
in the same transaction if none exists, so no folder group ever lacks a shelf
id and page. **Clearing a folder's `shelf_name` leaves the shelf standing**: a
shelf outlives its folders (9.1); the shelf is the thing and the name is its
membership. Name length matches `folder_members.shelf_name`'s bound.

**Covers follow 4.3's one-source rule**: at most one of `cover_file_id` and
`cover_preset`, and possibly neither, because `shelves_cover_file_id_fkey`'s
SET NULL produces the no-cover state when the picture is deleted. A shelf's
cover file is normally the person's own folder-less file (4.16); a file from a
folder they are a member of is admitted too, keeping the rule identical to
7.19's for a place page.
