### 4.26 folder_personal_labels

The second assignment relation, 4.25's shape one target over: one of the
viewer's own Personal Labels (4.24) applied to one Folder. Columns, constraints
and index: `app/db/migrations/0022_labels.sql`.

**There is no folder-scoped Label on a Folder, and that absence is the model.**
A Folder Label classifies the **Tasks inside** its Folder, never the Folder that
owns it, so the only Labels a Folder can carry are Personal ones; the NOT NULL
`owner_user_id` refuses the other kind for the reason 4.25 gives. A Folder
therefore carries exactly one Label projection on the wire, the viewer's own,
and two members reading one Folder read different arrays, as they read
different `my_shelf` values.

**A Personal Label applied to a Folder is still a Personal Label**: it is not
visible to the Folder's other members and acquires no scope of its own.

Cascade and archive behaviour are 4.25's: a soft-deleted Folder keeps its rows
and restores whole, only the purge takes them, and archiving a Label leaves
existing assignments standing.
