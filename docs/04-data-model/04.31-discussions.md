### 4.31 discussions

One row is one **Discussion** in one Folder's Consultation (issue #320, product
authority #212 R1, R2, R4). Columns, constraints and indexes:
`app/db/migrations/0029_consultation_discussions.sql`.

- `state` is exactly `open | resolved`; there are no Discussion types.
- `discussions_resolution_check` makes `resolved` equivalent to `resolved_at`
  being set, and an open Discussion never has a current Outcome. Since 0040
  (Wave 2 decision 3) a resolved one may have none: a thread can be closed
  without a decision. Resolve inserts the Outcome, when there is one, and flips
  the row in one transaction; reopen clears `current_outcome_id`, `resolved_at`
  and `resolved_by` and deletes nothing.
- `discussions_current_outcome_fkey` holds `(id, current_outcome_id)` against
  `discussion_outcomes (discussion_id, id)`, so the current Outcome is always
  one of the Discussion's own. It is NO ACTION because the two tables
  reference each other and a Folder purge cascades to both in one statement.
- `context` is plain text, at most 4000 characters, NULL when absent.
- `created_by` and `resolved_by` are provenance, never authority (#228); both
  keys on `users` are RESTRICT and outlive the account (8.10).
- `trashed_at` is Trash: non-destructive and restorable. Permanent purge is a
  DELETE, which cascades to the Discussion's Outcomes and comments.
- `last_activity_at` orders the Consultation list
  (`discussions_folder_activity_idx`, partial on `trashed_at IS NULL`).
- `is_general` marks the Folder's **General discussion**, the thread the
  pre-Consultation client reads and writes as the Folder conversation (7.14).
  It is a flag and never the title, so a rename moves nothing and another
  Discussion titled "General discussion" is ordinary. Set by the backfill and
  by the legacy post that creates one; nothing clears it.
  `discussions_one_open_general_key` (partial unique on `folder_id` where
  `is_general AND state = 'open' AND trashed_at IS NULL`) holds at most one
  open, untrashed one per Folder; resolved or trashed ones may sit beside it.
- `comments_unfiled_folder_idx` (on `comments (folder_id)` where `task_id` and
  `discussion_id` are both null) serves the legacy post's check for Folder-level
  comments no Discussion holds yet.
- **Discussion ↔ Task links** (migration 0066, #497) are rows of `discussion_tasks`
  (`discussion_id`, `task_id`, `created_via_task`, `created_at`; primary key on the pair),
  many to many: a Discussion may be about several tasks and a task may have several
  Discussions. A link is a reference, not containment. Moving to Trash touches no link
  on either side; permanently deleting either end removes only its links
  (`discussion_tasks_discussion_id_fkey` and `discussion_tasks_task_id_fkey`, both ON
  DELETE CASCADE), leaving the other end standing. A task's move leaves its Discussions,
  their comments and their files where they are. `created_via_task` records only that
  7.28's Discuss made the link, so Discuss can find its own thread again; a link made
  any other way stores false. A Discuss thread's title is the task's at creation and does
  not follow renames. 0066 copied every 0059 `discussions.task_id` into this table
  (`created_via_task` true where the Discussion was made at or after its task) and dropped
  that column and `discussions_one_live_per_task_key`.
- `discussions_folder_id_id_key` exists so `comments` can hold a composite key
  to `(folder_id, id)`: a comment's Discussion is in the comment's own Folder.

**Migration 0029's backfill.** Each Folder with Folder-level comments
(`task_id IS NULL`), trashed and default Desk Folders included, received exactly
one open Discussion titled "General discussion" with `is_general` true, `created_by` the Folder owner,
`created_at` its earliest comment's time and `last_activity_at` its latest, and
every such comment was pointed at it. Folders without Folder-level comments
received none.

**Migration 0059's move.** First, a live thread turned into a task before M5 (its
latest "Turned into a task: <link>" post naming a live task of the same Folder) is
linked to that task, one thread per task, and reopened (`resolved_at` and
`resolved_by` cleared) unless it carries a decision. Then each other task with comments, Desk
and trashed tasks included, received exactly one Discussion in its Folder with
`task_id` set, titled with the task (trimmed, cut to 200 characters, "Untitled task"
when blank), `created_by` its first poster, `created_at` its earliest comment's
time and `last_activity_at` its latest. It is live even for a trashed task (the
link hides a trashed task, restoring the task finds it, and a purge leaves it
standing), and open whatever the task's status, so every commenter keeps
editing and deleting their own words (a resolved thread takes no writes) and a
finished task can still be talked about. Every comment was re-pointed in place (`discussion_id`
set, `task_id` NULL) into its task's Discussion, a linked older thread included,
so its id, author, words, times, replies, reactions, files and mention notices are
unchanged. Each 4.35 row became the matching 4.34 row, and every other member of
the Folder was given a 4.34 row at the Discussion's last activity, so old talk
does not arrive unread. Tasks without comments received none.

**An unstarted task thread.** A Discussion "Discuss" made (its link has
`created_via_task`) that has no post, no input round, no context and no decision yet is not listed
(7.28) and not in its task's `linked_discussions`; the next "Discuss" reuses it. So looking
without talking leaves nothing behind.
