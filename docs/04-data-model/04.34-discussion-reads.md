### 4.34 discussion_reads

One row is **when one person last opened one Discussion**. Columns, constraints and
indexes: `app/db/migrations/0048_discussion_reads.sql`.

The row is written only by 7.28's `PUT /discussions/:id/read`, which upserts `read_at` to
now; no row means the person has never opened the thread. It is kept on the server, not in
the browser, so unread state follows a person between devices and opening a thread can
clear the bell for it. It is one person's own state: nobody else reads it, and no event
records it.

The Discussion key cascades, since a marker on a purged thread means nothing. The `users`
key cascades too but never fires, because 8.10 scrubs the `users` row rather than deleting
it; account deletion removes these rows itself.
