### 4.28 folder_responsibilities

One row is one member's **current** Responsibility document in one folder: rich
content in the same storage format 4.17 uses for page blocks (canonical shape
per 4.11), because it is something a person writes, with headings, bullets and
links. Columns, constraints and indexes:
`app/db/migrations/0025_responsibility_document.sql`.

**The partial unique index — one active document per (folder, member) where
`ended_at IS NULL` — carries the whole leave-and-rejoin rule.** Membership
ending stamps `ended_at`, which closes the standing and frees the slot, so a
rejoin writes a new row at revision 1 rather than reopening the old one. Nothing
is deleted, so history survives the membership it describes.

**There is deliberately no `ended_by`.** Who ended a standing is on the
`responsibility_ended` entry in 4.29, which is the authority; a copy here could
only drift.

**`content_hash` is the concurrency token** the API calls `revision`. A commit
sends the hash it read as `base_revision`; a commit whose content already hashes
to the current value is a no-op whatever it sent, and only otherwise is a stale
base refused with 409. That order makes a retry after a lost answer safe without
a receipts table.

**The two `users` keys are RESTRICT, not CASCADE.** Account deletion (8.10)
scrubs the `users` row rather than deleting it, so a CASCADE would delete
nothing while looking like cleanup; the 8.10 sweep closes the standing
explicitly instead, and RESTRICT makes a future hard delete fail loudly rather
than taking the folder's record of its own work.
