# M1 — Dana Core Work Model

Phase 1 of five (issue #202). Opened 2026-09-14, when M0 closed.

**Status lives in [#203](https://github.com/zhssnym/dana/issues/203), not here.**
That issue carries the implementation slices, their ordering, their dependencies and
what is done. This file carries only what M1 is for and what it should contain. Two
places tracking one thing is how a document starts lying, and the issue is the one that
updates itself.

As each item lands, its contract goes into `docs/spec/`, which is the authority on all
of them. This file is not amended to record that. It is rewritten once, in past tense,
on the day M1 closes.

## Outcome

A founder can use Dana's ordinary Work model coherently:

> **Main | Purpose | Consultation | Results | +**

M1 should feel like one Work model rather than several unrelated pages. One
authoritative home for each fact: Task state belongs to Main, intended direction to
Purpose, deliberation to Consultation, actual outcomes to Results. Other surfaces
reference those facts rather than copying them.

## What M1 contains

Approved 2026-09-14, amended 2026-09-18. This is the Dana Work Model direction as
Imran wrote it.

1. **Start dates on Tasks.**

2. **BlockNote and Context foundation.**
   - Targeted BlockNote across Task, Folder and Shelf.
   - Headings H1 to H3, which form the default collapsible Section hierarchy.
   - File attachments, bulleted lists, numbered lists, checklists, media insertion
     (audio, video, images), quotes, callouts, diagrams and code blocks.

3. **Task relationships and dependencies.**
   - Tasks may reference other Tasks.
   - Dana links display as UI chips for Tasks, Folders and Shelves.
   - Relationships such as blocked by / blocking.

4. **Tags and Labels.**
   - Standardised across the appropriate Work Units.
   - Included in filters and Views.

5. **Responsibilities and Authorities.**
   - Responsibilities for Folder members.
   - Distinct Authority levels for members.

6. **Purpose.** The Folder-level Purpose facet, with the Dana BlockNote composer and
   Dana Links.

7. **Consultation / Discussion.** Folder-level Consultation: Topics, Comments, Replies
   and Voting, able to reference Purpose, Tasks, Sections, Results and other Work
   items. Reuse Dana's existing discussion system where possible rather than building a
   second one.

8. **Results / Outcome.** The Folder-level Results facet, with the Dana BlockNote
   composer and Dana Links.

9. **Core Folder facet strip.** **Main | Purpose | Consultation | Results | +**, with
   canonical facets hideable and unhideable. In M1, `+` adds only blank composer facets
   and saved Views.

10. **Task indicators.** Finite Task progress on Folders and Sections, such as
    17/22 done, with recurring Tasks kept out of the finite denominator.

## Not in M1

AI agent personas and AI Folder membership; broad contextual AI; an advanced
milestone or phasing model; public plugins; generalised domain facets; a universal
workflow engine; speculative structural systems M1 does not require.

Reusable workflows already exist in Dana. They are not a future milestone feature, and
may be refined later alongside other structural parts of the product.

M2 and later direction is in #202.
