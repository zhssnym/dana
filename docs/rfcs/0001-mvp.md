# RFC 0001: MVP

**Status:** implemented
**Milestone:** none, this RFC predates the milestone process

The one-time work order that took the repository from empty to Dana 1.0.0, released
2026-08-16: a collaborative to-do PWA, entirely manual, no AI and no integrations.
Thirteen packages ran in dependency order, one agent session each. The product is the
running app and the acceptance suite, so the plan itself is not kept.

What survives is the bet the plan rested on, because nothing else in the repository
records it. Writing the specification as the code went along, the default for human
teams, was rejected. The implementers were AI agents in isolated sessions with no
channel back to a human reviewer, and an agent cannot resolve an ambiguity in a
hallway: every gap in a partial spec becomes a silent wrong guess rather than a
question. So the whole contract was written first, a data model with named invariants,
exact query orderings, an API, normative UI copy, a decided architecture and 115
numbered acceptance criteria written by a role that never implements. Then sections 4
and 7 were frozen. That is the project's core bet, and it is why `docs/spec/` exists in
the shape it does.

The product and stack alternatives this RFC listed are not repeated. They are normative
in the spec with their reasons, in section 1.3 and section 11.14.
