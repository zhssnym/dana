### 11.14 Rejected alternatives

Recorded so future work argues with a decision instead of rediscovering it. External facts
(prices, plan limits, maintenance status) were true when each decision was made.

| Alternative | Rejected because |
| - | - |
| Next.js (App Router) | Server actions and RSC data paths are a second door past the section 7 contract and the 10.2 chokepoint; the framework is mid-churn, which is where agents invent; SSR has no consumer in a login-gated PWA |
| Vercel hosting | No always-on process for the 8.6 tick; ephemeral instances break 10.4's in-memory rate limiting; honest total cost about triple Render, across three vendors |
| Railway | Close second: always-on and cheaper, but snapshot backups only, no point-in-time recovery |
| Fly.io | No free allowance for new accounts and expensive managed Postgres; the cheap path is self-operated Postgres, which the project constraints exclude |
| Supabase | Free tier pauses when idle and has no automated backups; its native pattern (client-side data access behind RLS) is what 10.2 forbids; Pro costs more than this entire stack |
| Neon | Scale-to-zero is defeated by the one-minute poll, so its pricing works against exactly this workload |
| Auth.js (NextAuth) | In maintenance mode; v5 never left beta |
| Better Auth | Would own the users table shape and the provisioning transaction that section 4 and AC-005/AC-006 fix; its release cadence outruns agent training data; it is the designated fallback if hand-rolled auth is ever vetoed |
| Lucia, Arctic | Both deprecated by their author |
| Prisma | Schema DSL far from section 4's SQL; heavier runtime; worse fit for constraint-exact migration work |
| rrule.js at runtime | Unmaintained; its reinterpreted-UTC result model collides with floating dates; kept as a test oracle only |
| FullCalendar for the calendar grid | The visible Q3C order is the contract, and a grid Dana renders orders cells by rendering them in order, with no comparator or overlay; 9.5's fixed six-week height and "+N more" overflow are layout the library has opinions about. The cost is that grid accessibility and keyboard handling are Dana's own (9.1) |
| Serwist | Coupled to Next.js, which was rejected |
| GitHub Actions as the reminder trigger | Documented 5-minute floor, plus documented delays and dropped runs under load |
| Buying GitHub-hosted CI minutes | The owner's choice; the self-hosted runner is deliberate. Hosted runners remain admissible under 11.11, the workflow differing only in `runs-on` and in where the Postgres leg's database comes from |
| Matching a Linux image's libc locale on the self-hosted runner | Windows has no glibc, so the same locale name selects a different implementation and the orderings would still differ by an unknown amount: fidelity claimed and not held (11.10) |
| ICU as the test database's locale provider | Deterministic across operating systems only within one ICU major version, which nothing pins; it would be a third ordering agreeing with neither PGlite nor a glibc production database, buying a linguistic collation at the cost of the byte-identical results section 6 asks for |
| Standing staging environment | Doubles hosting cost to serve zero users; the Postgres test leg plus the production smoke covers it (11.11) |
| pnpm, workspaces | Real virtues, but nothing here ships separately and one npm package is simpler |
| `.strict()` across the request schemas of `app/src/shared/` | 7.0 tolerates unknown fields deliberately; see below |
| Per-viewer folder identity | Lost to folder-owned identity. A collaboration product where every member sees a different page is two products, and the per-member table also doubles the sharing system |
| CRDTs for page blocks | Lost to last-write-wins plus 409. Dana's concurrency is two people occasionally rather than documents-as-a-service, and 8.3 already had the conflict vocabulary |
| Real-time push for comments | Lost to refetch-and-poll: no new architecture, and the single instance 11.1 assumes stays intact. Deferred by name rather than denied |
| A reminders redesign | Lost to the existing `time_of_day` mode. The schema already answered day-level reminders, so a new column would have been a worse copy of 4.8 |
| Trash as its own table | Lost to `deleted_at` columns. Users already soft-delete this way, so it is one pattern and restore is an UPDATE |

**Why `.strict()` is rejected.** A request field the server does not read is accepted,
dropped, and answered 200, and the complaint is real; strictness is the wrong remedy for
three reasons.

- **It is blind to the costly failure.** The field loss that matters is one the schema
  declares and the route never acts on (11.15), and strictness reads only undeclared keys.
- **It breaks `POST /workflows/import` against Dana's own normaliser.** 7.16's import folds
  the arrangements real files arrive in and copies rather than moves, leaving undeclared
  keys at several levels, so a strict canonical schema would refuse files on the endpoint
  most deliberately widened to be forgiving.
- **It turns version skew into failure.** 10.6 lets an installed client outlive a deploy
  with no forced reload, the only source of skew one deployable leaves open. Under
  tolerance a field dropped from a request schema is an old client degrading quietly;
  under strictness it is that person's writes failing until they reload.

What is done instead, none of it a change to section 7:

- **An endpoint that deliberately refuses a field declares it and refuses it**:
  `field: z.never({ error: … }).optional()` answers 422 naming the field while every other
  unknown key stays tolerated.
- **A field a request schema declares is read in the same change**, and a criterion proves
  it (AC-149).
- **Unknown fields are observed, not refused**: `parseBody` in
  `app/src/server/http/parse-body.ts` is how every route reads a body (AC-399, AC-400); it
  parses as `safeParse` does and writes one warn-level `unknown_request_fields` line naming
  the route template and key names, never values (10.5). It observes the top level only.
