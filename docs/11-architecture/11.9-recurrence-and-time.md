### 11.9 Recurrence and time

- The 4.11 RRULE subset is implemented by an in-repo iterator module, not a runtime
  library, because rrule.js is unmaintained and models results as reinterpreted UTC Dates,
  which collides with Dana's floating dates. The iterator is differential-tested against
  rrule (a development-only oracle); where they disagree, RFC 5545 adjudicates, never the
  oracle.
- UNTIL is written in RFC 5545's DATE form, YYYYMMDD, and a rule string spelling it any
  other way is outside the 4.11 subset and answers 422 like any other free-form input.
  Within an RRULE value the DATE form carries no separators, so the extended spelling is
  not a valid value of the RFC 4.11 names, and 4.11's rule that only strings the preset
  builder can produce are valid forecloses accepting both. The dates this specification
  writes and its wire fields carry stay in extended form; the interior of a value string
  another standard defines is that standard's. The oracle parses the basic form, so
  nothing translates between Dana's string and the oracle's.
- Luxon performs all IANA timezone math. Both DST rules of 8.6 are implemented explicitly
  in the fire-instant module because Luxon guarantees neither: for a nonexistent local
  time Luxon advances by the gap length (02:30 becomes 03:30) where 8.6 requires the first
  valid instant after the gap (03:00), so the module detects the gap and clamps; for an
  ambiguous local time Luxon's documentation declares the choice undefined, so the module
  selects the earlier instant itself. AC-144 and AC-145 state the two rules; AC-083 to
  AC-086 state the zone arithmetic they sit on.
