### 7.21 Place descriptions

The wire half of 4.22.

GET /api/v1/place-descriptions — { descriptions: [ { place, description } ] },
the caller's own. **The read is dense**: every one of 4.22's places
appears, in 9.1's fixed order, carrying `null` where the caller has written
nothing. Null means Dana's own sentence for that page, which stays in the
client (`routes.ts`) and is never sent from here, so the server keeps no copy
of copy it would have to keep in step.

PUT /api/v1/place-descriptions/:place — body { description }, a string of at
most 500 characters or null; the field is required and 422 names it when it
is absent, an optional field the server ignored being one the API would
accept and drop with a 200. Null clears, and so does a string of nothing but
whitespace, because a person who empties a textarea has cleared it whatever
the browser sends; the stored value is trimmed and that is what reads back.
Idempotent, 200 with the entry.

`:place` is 4.22's set, which is 4.20's, and anything else is 404: a place
page is furniture rather than a resource that might exist somewhere the
caller cannot see, and `desk` is a folder whose description is 7.4's. There
is no DELETE, PUT with null being the same act and the only one the control
performs.

Descriptions are the caller's own throughout: no route reads or writes
another person's, and both routes require a session — the read as much as the
write, since nothing structural checks a GET.

The write is CSRF-checked and under 10.4's general mutation limit.
