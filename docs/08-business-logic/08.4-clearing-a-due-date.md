### 8.4 Clearing a due date

Implementation: `patchTask` in `app/src/server/domain/tasks.ts`. Every cascade below runs
in the same transaction as the PATCH that causes it.

- **Clearing due_date** (PATCH due_date := null, by a member of the task's folder) also
  nulls due_time (INV-6), nulls recurrence_rule when set (the series ends; series_id stays
  for history), and deletes the task's reminder. The client warns first when a rule or
  reminder exists: "Clearing the date also ends the repeat and removes the reminder." The
  database checks of 4.5 make the ordering unskippable.
- **A PATCH that invalidates the reminder's mode deletes the reminder.** 4.8 ties the mode
  to due_time: offset requires it and time_of_day requires its absence. So clearing
  due_time deletes an offset reminder, and setting due_time from null deletes a
  time_of_day reminder.
- A due_time that moves from one time to another, rather than across the null boundary,
  invalidates no mode and cascades nothing; it is an ordinary 8.6 recompute trigger.
- The delete precedes any recompute: the recompute refuses a shape it cannot compute, and
  after the delete there is no row to recompute.

Why a cascade rather than the alternatives: refusing with 422 would block an edit the user
is entitled to make over a row they may have forgotten setting, and converting the mode
would silently change when the reminder fires by inventing a time or offset nobody chose.
The time-set arm cascades even though its shape would still compute, because 4.8 forbids
the pair and the reminder control (9.3) could neither render nor edit it.
